# Решения

Формат: решение → почему. Статус «предложено» = ждёт подтверждения Романа (см. `questions.md`), «принято» = действует.

## D1. Структура репозитория — принято
Ядро (`Conversions`, `Engines`, `Jobs`) вынесено в отдельную библиотеку `DropWheel.Core` (net8.0, без WPF). Так CLI и тесты собираются и запускаются на Linux, а WPF-приложение (`net8.0-windows`) только ссылается на ядро. Папки `App/Input/Wheel/Shell/Settings` из ТЗ живут в WPF-проекте.

## D2. Запуск внешних утилит — принято
Аргументы передаются через `ProcessStartInfo.ArgumentList` (без склейки строки и ручных кавычек) — кириллица и пробелы в путях работают без экранирования. Вывод читается в UTF-8.

## D3. Запись результата — принято
Конвертер пишет во временный файл рядом с целевым (`.dropwheel-tmp`), по успеху переименовывает в итоговое имя. Если процесс упал — временный файл удаляется, полу-готовых файлов не остаётся. Имя подбирается непосредственно перед переименованием, чтобы не затереть файл, появившийся за время конвертации.

## D4. ffmpeg: GPL-сборка — предложено
В LGPL-сборке ffmpeg нет кодировщика libx264, а он нужен для «→ MP4 (H.264)». Для личного некоммерческого проекта GPL-сборка допустима (например, gyan.dev «essentials» или BtbN «gpl»). Альтернатива — аппаратный/системный `h264_mf` из Windows, но качество и управляемость хуже.

## D5. Перетаскивание из браузера — предложено
Из браузера часто приходит не файл на диске (CF_HDROP), а ссылка или «виртуальный файл» (FileGroupDescriptor/FileContents). У такого файла нет «соседней папки». Предложение: сохранять такие результаты в `Загрузки\DropWheel`.

## D6. Мультивыбор в контекстном меню — предложено
Проводник для пункта меню через реестр запускает отдельный процесс на каждый выделенный файл и по умолчанию не показывает пункт, если выделено больше 15 файлов (`MultipleInvokePromptMinimum`). Решение: первый экземпляр собирает пути от остальных через named pipe в течение ~300 мс после последнего пришедшего пути и только потом показывает колесо/меню один раз. Лимит 15 — ограничение MVP (для больших пачек — позже «обработка папки»).

## D7. Shift/Ctrl/Alt как горячая клавиша — предложено
Противоречит обоснованию из раздела 3 ТЗ: во время перетаскивания эти клавиши меняют действие проводника (переместить/копировать/ярлык). Предложение: убрать их из списка вариантов.

## D8. Анимированный GIF на входе — предложено
В ТЗ не описан. Предложение: считать анимированный GIF видео — предлагать → MP4 / WebM; статичный GIF — как картинку. Определять по числу кадров (magick identify).

## D9. Окна администратора (UIPI) — ограничение MVP
Если окно-источник или целевое окно запущено от администратора, а DropWheel — нет, хуки и drop в колесо не сработают. Записываем как известное ограничение, ничего не делаем.

## D10. DragEnter в колесе — к проверке на этапе 3
В OLE-цикле перетаскивания `DragEnter` новому окну приходит только после следующего движения мыши. Если колесо появилось под неподвижным курсором, сектора построятся с задержкой. Возможное решение — программно сдвинуть курсор на 1 px после показа окна. Проверить на этапе 3.

## D11. ImageMagick 7 — принято
Для Windows берётся portable ImageMagick 7 (`magick.exe`). Аргументы строятся в синтаксисе IM7 (`magick вход [операции] выход`), который совместим и с IM6 (`convert`) в используемом подмножестве — это позволяет гонять интеграционные тесты на Linux.

## D12. Пометка в имени у инструментов — принято
Инструменты (сжать, уменьшить, без звука…) дают файл того же формата, и `photo (1).jpg` ничего не говорит о содержимом. Поэтому к имени добавляется пометка: `photo (сжато).jpg`, `clip (720p).mp4`, `song (норм).flac`. Правило «занято → (1), (2)» действует поверх неё. Конвертации пометки не добавляют (`photo.heic` → `photo.jpg`).

## D13. Детали операций — принято
- Конвертация в тот же формат не предлагается (`.jpg` → «JPG» скрыт, синонимы jpg/jpeg, tif/tiff, heic/heif, mp4/m4v учитываются). Инструменты для того же формата предлагаются.
- Картинки: берётся первый кадр (`[0]`), применяется `-auto-orient`; для JPG и PDF прозрачность заливается белым. PDF — с JPEG-сжатием (иначе огромный).
- Инструменты для картинок сохраняют формат, если он «обычный» (jpg/png/webp/bmp/tiff/gif); HEIC/AVIF → JPG. «Сжать» даёт JPG, а WebP оставляет WebP.
- «До 1920» только уменьшает, маленькие картинки не растягивает.
- Видео → H.264: размеры кадра приводятся к чётным (иначе libx264 падает), `+faststart` для быстрого старта в браузере. «720p» уменьшает короткую сторону — вертикальное видео остаётся вертикальным.
- «Нормализовать» (loudnorm) — формат сохраняется, частота 48 кГц.
- Качество по умолчанию: JPG 90, WebP 85, AVIF 70, CRF 23 (сжатие — 28), MP3 192k.

## D14. Как Роман получает сборку — принято
Из облачной сессии нельзя скачать ffmpeg/ImageMagick для Windows (сеть закрыта). Сборку делает GitHub Actions (`.github/workflows/build.yml`): тесты на Linux и на Windows с настоящими утилитами, затем архив `DropWheel-win-x64.zip` (self-contained exe + `tools/`) выкладывается в релиз `dev-build`, который перезаписывается при каждом пуше. Утилиты качает `build/fetch-tools.ps1`: ffmpeg — GPL-сборка BtbN, самая новая release-ветка (сейчас 9.0; см. D4), ImageMagick 7 portable Q16.

## D15. Тесты на Linux — принято
В облаке стоит ImageMagick 6 (`convert`), ImageMagick 7 недоступен. ToolLocator при отсутствии `magick` берёт `convert` — синтаксис используемых команд совпадает. Эталонный HEIC (`tests/.../Fixtures/sample.heic`) лежит в репозитории, остальные исходники тесты генерируют через ffmpeg. Без утилит интеграционные тесты пропускаются.

## D16. Меню из проводника на этапе 2 — список, колесо позже — принято
По ТЗ клик по «Конвертировать…» открывает «то же колесо или компактное списочное меню». На этапе 2 — обычное контекстное меню WPF у курсора (надёжно, привычно). Колесо в режиме клика уже написано (`WheelWindow`), включим его в этом сценарии после проверки колеса на этапе 3.

## D17. Пункт меню: MultiSelectModel=Player — к проверке
Ключ `MultiSelectModel=Player` должен снимать предел проводника в 15 файлов (см. D6, вопрос 3). Процессов всё равно запускается по одному на файл — первый экземпляр собирает пути 300 мс. Проверить на Windows (чек-лист, этап 2, пункт 5).

## D18. Два exe в одной папке — принято
`DropWheel.exe` (приложение) и `dropwheel-cli.exe` (консоль). Имена различаются не только регистром: в Windows `DropWheel.exe` и `dropwheel.exe` — один и тот же файл. Оба — self-contained single-file со сжатием.

## D19. Хуки и колесо — заранее, к этапу 3 — принято
Детектор перетаскивания (`DragDetector`, чистая логика с тестами), low-level хуки на отдельном потоке со своим циклом сообщений, окно колеса (`WheelWindow`, позиционирование в физических пикселях с учётом DPI монитора) написаны параллельно с этапом 2, но к приложению ещё не подключены. Подключение — этап 3.

## D20. PDF — принято
- Движки: **qpdf** (склеить, разбить, оптимизировать) и **pdftoppm** из poppler (страницы → PNG/JPG, 150 dpi, JPG качество 90). Windows-сборки: qpdf — официальная MSVC (Apache-2.0), poppler — oschwartz10612/poppler-windows (GPL-2.0+); их качает `build/fetch-tools.ps1` в `tools/qpdf`, `tools/poppler`.
- «Разбить» и «PNG/JPG (страницы)» дают папку рядом с исходником: `тест 1 (по страницам)`, `тест 1 (страницы)`. Внутри файлы `стр-1.pdf`, `стр-2.png`…; номера дополняются нулями по числу страниц (10+ страниц → `стр-01`), чтобы файлы шли по порядку при сортировке по имени.
- «Склеить» — 2+ PDF в один, в том порядке, в каком пришли файлы, имя по первому: `тест 1 (объединено).pdf`.
- «Оптимизировать» — без потерь: потоки объектов, пережатие flate на уровне 9. Картинки внутри не пережимаются, поэтому сильно уменьшаются только «рыхлые» PDF. Сжатие с потерями (Ghostscript) — не в этом этапе.
- qpdf с кодом выхода 3 («есть предупреждения», например, починил битую таблицу xref) — успех: файл записан.
- «Один PDF» для картинок — 2+ картинки, каждая страницей (первый кадр, `-auto-orient`, JPEG-сжатие, прозрачность на белом), имя по первой: `фото (все).pdf`. Все картинки ImageMagick держит в памяти одновременно — для пачки больших фото это долго и много памяти.

## D21. ZIP — встроенный движок — принято
- Упаковка и распаковка — средствами .NET (System.IO.Compression), без 7-Zip.
- «В ZIP» подходит к любому файлу; выбранные файлы — в один архив. Имя: один файл — как файл (`photo.jpg` → `photo.zip`); несколько — по папке первого файла (`Отпуск\1.jpg`, `Отпуск\2.jpg` → `Отпуск.zip`, как «Добавить к "Отпуск.zip"» в 7-Zip; в корне диска — по первому файлу). Одинаковые имена из разных папок → `name (1).ext`. Имена записей — в UTF-8 с флагом UTF-8 (проводник Windows 10/11 показывает кириллицу правильно).
- Поэтому пункт «Конвертировать…» регистрируется для всех файлов (`HKCU\Software\Classes\*\shell\DropWheel.Convert`); старые ключи по расширениям удаляются при установке. Папки пока не регистрируются.
- «Распаковать» — в папку с именем архива (`photos.zip` → `photos`, занято → `photos (1)`). Архив целиком отклоняется, если в нём пути за пределы папки (`..`, абсолютные пути, буквы дисков — Zip Slip), записи с паролем, больше 100 000 записей или больше 20 ГБ после распаковки (константы в `ZipEngine`). Недопустимые в Windows символы в именах → `_`.
- Имена без флага UTF-8: если байты — корректный UTF-8 (macOS, Linux), читаем как UTF-8, иначе — как CP866 (старые архиваторы и «Сжатая папка» русской Windows).

## D-7ZIP. Архивы через 7-Zip, PDF → TXT, поворот PDF — принято
- **7-Zip** — внешняя утилита: `tools/7zip/7z.exe` + `7z.dll` (полная версия, в ней и RAR; урезанные 7za/7zr RAR не умеют). Windows-сборка — официальная, из релизов GitHub `ip7z/7zip`: `build/fetch-tools.ps1` скачивает `7zr.exe` и установщик `7zNNNN-x64.exe` и распаковывает установщик через `7zr.exe`, не запуская его (запасной путь — 7-Zip, установленный в системе); в `tools/7zip` остаются только `7z.exe`, `7z.dll`, `License.txt`. На Linux (тесты) — пакет `7zip`, команда `7z`.
- ZIP по-прежнему распаковывает встроенный ZipEngine (D21). «Распаковать» для 7z, RAR, TAR, GZ, TGZ, BZ2, XZ — 7-Zip: `x -y -bso0 -bsp1 -sccUTF-8 -o<временная папка> -pnopassword -- <архив>`. Папка — по имени архива без «.tar»: `фото.tar.gz` → `фото`, занято → `фото (1)`.
- `.tar.gz`, `.tgz`, `.tar.bz2`, `.tar.xz`: 7-Zip за один запуск снимает только сжатие и кладёт один `.tar`. Если после распаковки .gz/.tgz/.bz2/.xz в папке ровно один файл и это tar (подпись `ustar`), DropWheel распаковывает его вторым запуском, а сам `.tar` не оставляет (на время распаковки нужно место и под `.tar`, и под файлы). Обычный `.gz` с одним файлом (`заметка.txt.gz`) просто распаковывается.
- Пароль: `-p` с выдуманным паролем, чтобы 7-Zip не ждал ввода (и у всех утилит теперь пустой stdin). Архив с паролем → «Архив с паролем не поддерживается».
- Безопасность (проверено тестами на 7-Zip 23.01, Linux): `..` и абсолютные пути 7-Zip отрезает сам — файлы остаются внутри папки (`../evil.txt` → `evil.txt`, `/tmp/x` → `tmp/x`); символические и жёсткие ссылки за пределы папки не создаёт («Dangerous link path was ignored») и завершается с ошибкой → «Архив небезопасен: в нём ссылки за пределы папки». Распаковка идёт во временную папку; при любой ошибке она удаляется целиком. На Windows это поведение не проверено вручную — тест там проверяет только, что за пределы папки ничего не записано. Лимитов, как у ZIP (20 ГБ / 100 000 файлов), нет: заранее их не проверить; кончится место — «Закончилось место на диске».
- «В 7Z» — любые файлы, все выбранные в один архив: `a -t7z -mx=7 -bso0 -bsp1 -sccUTF-8 -spd -sse <архив> -- <файлы>`. Пути передаются полными, но 7-Zip хранит только имена файлов, без папок; имена — в Unicode (кириллица сохраняется). Имя архива — как у «В ZIP» (`ZipEngine.ArchiveName`). Одинаковые имена из разных папок 7-Zip не принимает → «В 7Z нельзя положить файлы с одинаковыми именами из разных папок» (ZIP такие переименовывает). `-spd` — `*` и `?` в именах не считаются масками; `-sse` — не удалось открыть файл → архив не создаётся. `--` — дальше только пути (имя на `-` или `@` не примется за ключ).
- Коды выхода 7-Zip: успех — только 0. Код 1 («предупреждения») — ошибка: при упаковке он значит, что какой-то файл не попал в архив.
- Прогресс: с `-bsp1` 7-Zip пишет « 43%» в stdout без перевода строки и стирает его символами `\b`; EngineRunner читает stdout 7-Zip кусками (SevenZipProgress). У `.tar.gz` — по половине шкалы на каждый запуск.
- RAR тестами не проверен: создать RAR здесь нечем (WinRAR платный). Распаковка RAR — через `7z.dll`.
- **PDF → TXT** («TXT (текст)») — `pdftotext` из той же сборки poppler, что и pdftoppm: `-layout -enc UTF-8`. `-layout` сохраняет колонки и отступы; `-enc UTF-8` обязателен — в Windows pdftotext по умолчанию пишет Latin-1, и кириллица пропала бы. Переводы строк в Windows — CRLF (по умолчанию). Если в результате нет ни одной буквы или цифры (у скана — только разрывы страниц), файл не создаётся: «В PDF нет текстового слоя (это скан)» — для сканов нужно распознавание текста (OCR). Автор PDF запретил копирование текста → «Автор PDF запретил копировать из него текст».
- **Повернуть ↻** — `qpdf --rotate=+90`: все страницы на 90° по часовой стрелке без перекодирования (меняется только `/Rotate` страниц). Повторный поворот добавляет ещё 90°. Имя: `тест 1 (повёрнуто).pdf`.
