# Решения

Формат: решение → почему. Статус «предложено» = ждёт подтверждения Романа (см. `questions.md`), «принято» = действует.

## D1. Структура репозитория — принято
Ядро (`Conversions`, `Engines`, `Jobs`) вынесено в отдельную библиотеку `DropWheel.Core` (net8.0, без WPF). Так CLI и тесты собираются и запускаются на Linux, а WPF-приложение (`net8.0-windows`) только ссылается на ядро. Папки `App/Input/Wheel/Shell/Settings` из ТЗ живут в WPF-проекте.

## D2. Запуск внешних утилит — принято
Аргументы передаются через `ProcessStartInfo.ArgumentList` (без склейки строки и ручных кавычек) — кириллица и пробелы в путях работают без экранирования. Вывод читается в UTF-8.

## D3. Запись результата — принято
Конвертер пишет во временный файл рядом с целевым (`.dropwheel-tmp`), по успеху переименовывает в итоговое имя. Если процесс упал — временный файл удаляется, полу-готовых файлов не остаётся. Имя подбирается непосредственно перед переименованием, чтобы не затереть файл, появившийся за время конвертации.

## D4. ffmpeg: GPL-сборка — предложено
В LGPL-сборке ffmpeg нет кодировщика libx264, а он нужен для «→ MP4 (H.264)». Для личного некоммерческого проекта GPL-сборка допустима (например, gyan.dev «essentials» или BtbN «gpl»). Альтернатива — аппаратный/системный `h264_mf` из Windows, но качество и управляемость хуже.

## D5. Перетаскивание из браузера — заменено решением D-BROWSER
Из браузера часто приходит не файл на диске (CF_HDROP), а ссылка или «виртуальный файл» (FileGroupDescriptor/FileContents). У такого файла нет «соседней папки». Предлагалось сохранять такие результаты в `Загрузки\DropWheel`; сделано иначе — в ту же папку, что и картинки из буфера обмена (см. D-BROWSER).

## D6. Мультивыбор в контекстном меню — предложено
Проводник для пункта меню через реестр запускает отдельный процесс на каждый выделенный файл и по умолчанию не показывает пункт, если выделено больше 15 файлов (`MultipleInvokePromptMinimum`). Решение: первый экземпляр собирает пути от остальных через named pipe в течение ~300 мс после последнего пришедшего пути и только потом показывает колесо/меню один раз. Лимит 15 — ограничение MVP (для больших пачек — позже «обработка папки»).

## D7. Shift/Ctrl/Alt как горячая клавиша — предложено (своя клавиша их тоже не принимает, см. D-HOTKEY)
Противоречит обоснованию из раздела 3 ТЗ: во время перетаскивания эти клавиши меняют действие проводника (переместить/копировать/ярлык). Предложение: убрать их из списка вариантов.

## D8. Анимированный GIF на входе — предложено
В ТЗ не описан. Предложение: считать анимированный GIF видео — предлагать → MP4 / WebM; статичный GIF — как картинку. Определять по числу кадров (magick identify).

## D9. Окна администратора (UIPI) — ограничение MVP
Если окно-источник или целевое окно запущено от администратора, а DropWheel — нет, хуки и drop в колесо не сработают. Записываем как известное ограничение, ничего не делаем.

## D10. DragEnter в колесе — к проверке на этапе 3
В OLE-цикле перетаскивания `DragEnter` новому окну приходит только после следующего движения мыши. Если колесо появилось под неподвижным курсором, сектора построятся с задержкой. Возможное решение — программно сдвинуть курсор на 1 px после показа окна. Проверить на этапе 3.

## D11. ImageMagick 7 — принято
Для Windows берётся portable ImageMagick 7 (`magick.exe`). Аргументы строятся в синтаксисе IM7 (`magick вход [операции] выход`), который совместим и с IM6 (`convert`) в используемом подмножестве — это позволяет гонять интеграционные тесты на Linux.

## D12. Пометка в имени у инструментов — принято
Инструменты (сжать, уменьшить, без звука…) дают файл того же формата, и `photo (1).jpg` ничего не говорит о содержимом. Поэтому к имени добавляется пометка: `photo (сжато).jpg`, `clip (720p).mp4`, `song (норм).flac`. Правило «занято → (1), (2)» действует поверх неё. Конвертации пометки не добавляют (`photo.heic` → `photo.jpg`).

## D13. Детали операций — принято
- Конвертация в тот же формат не предлагается (`.jpg` → «JPG» скрыт, синонимы jpg/jpeg, tif/tiff, heic/heif, mp4/m4v учитываются). Инструменты для того же формата предлагаются.
- Картинки: берётся первый кадр (`[0]`), применяется `-auto-orient`; для JPG и PDF прозрачность заливается белым. PDF — с JPEG-сжатием (иначе огромный).
- Инструменты для картинок сохраняют формат, если он «обычный» (jpg/png/webp/bmp/tiff/gif); HEIC/AVIF → JPG. «Сжать» даёт JPG, а WebP оставляет WebP.
- «До 1920» только уменьшает, маленькие картинки не растягивает.
- Видео → H.264: размеры кадра приводятся к чётным (иначе libx264 падает), `+faststart` для быстрого старта в браузере. «720p» уменьшает короткую сторону — вертикальное видео остаётся вертикальным.
- «Нормализовать» (loudnorm) — формат сохраняется, частота 48 кГц.
- Качество по умолчанию: JPG 90, WebP 85, AVIF 70, CRF 23 (сжатие — 28), MP3 192k.

## D14. Как Роман получает сборку — принято
Из облачной сессии нельзя скачать ffmpeg/ImageMagick для Windows (сеть закрыта). Сборку делает GitHub Actions (`.github/workflows/build.yml`): тесты на Linux и на Windows с настоящими утилитами, затем архив `DropWheel-win-x64.zip` (self-contained exe + `tools/`) выкладывается в релиз `dev-build`, который перезаписывается при каждом пуше. Утилиты качает `build/fetch-tools.ps1`: ffmpeg — GPL-сборка BtbN, самая новая release-ветка (сейчас 9.0; см. D4), ImageMagick 7 portable Q16.

## D15. Тесты на Linux — принято
В облаке стоит ImageMagick 6 (`convert`), ImageMagick 7 недоступен. ToolLocator при отсутствии `magick` берёт `convert` — синтаксис используемых команд совпадает. Эталонный HEIC (`tests/.../Fixtures/sample.heic`) лежит в репозитории, остальные исходники тесты генерируют через ffmpeg. Без утилит интеграционные тесты пропускаются.

## D16. Меню из проводника — то же колесо в режиме клика — принято
По ТЗ клик по «Конвертировать…» открывает «то же колесо или компактное списочное меню». На этапе 2 было обычное контекстное меню WPF у курсора. Теперь — то же колесо (`WheelWindow`, `CloseOnDeactivate`) у курсора: клик по сектору — запуск; Tab, правая кнопка или клик по точкам в центре — «Конвертация ↔ Инструменты»; стрелки/колёсико мыши и Enter — выбор с клавиатуры; Esc, клик мимо или переход в другое окно — закрыть. Мышь захватывается, как у обычного меню, поэтому клик мимо закрывает колесо, даже если Windows не дала ему фокус. Старое списочное меню (`ChooserMenu`) осталось запасным: показывается, только если колесо не открылось (причина пишется в журнал).

## D17. Пункт меню: MultiSelectModel=Player — к проверке
Ключ `MultiSelectModel=Player` должен снимать предел проводника в 15 файлов (см. D6, вопрос 3). Процессов всё равно запускается по одному на файл — первый экземпляр собирает пути 300 мс. Проверить на Windows (чек-лист, этап 2, пункт 5).

## D18. Два exe в одной папке — принято
`DropWheel.exe` (приложение) и `dropwheel-cli.exe` (консоль). Имена различаются не только регистром: в Windows `DropWheel.exe` и `dropwheel.exe` — один и тот же файл. Оба — self-contained single-file со сжатием.

## D19. Хуки и колесо — заранее, к этапу 3 — принято
Детектор перетаскивания (`DragDetector`, чистая логика с тестами), low-level хуки на отдельном потоке со своим циклом сообщений, окно колеса (`WheelWindow`, позиционирование в физических пикселях с учётом DPI монитора) написаны параллельно с этапом 2, но к приложению ещё не подключены. Подключение — этап 3.

## D20. PDF — принято
- Движки: **qpdf** (склеить, разбить, оптимизировать) и **pdftoppm** из poppler (страницы → PNG/JPG, 150 dpi, JPG качество 90). Windows-сборки: qpdf — официальная MSVC (Apache-2.0), poppler — oschwartz10612/poppler-windows (GPL-2.0+); их качает `build/fetch-tools.ps1` в `tools/qpdf`, `tools/poppler`.
- «Разбить» и «PNG/JPG (страницы)» дают папку рядом с исходником: `тест 1 (по страницам)`, `тест 1 (страницы)`. Внутри файлы `стр-1.pdf`, `стр-2.png`…; номера дополняются нулями по числу страниц (10+ страниц → `стр-01`), чтобы файлы шли по порядку при сортировке по имени.
- «Склеить» — 2+ PDF в один, в том порядке, в каком пришли файлы, имя по первому: `тест 1 (объединено).pdf`.
- «Оптимизировать» — без потерь: потоки объектов, пережатие flate на уровне 9. Картинки внутри не пережимаются, поэтому сильно уменьшаются только «рыхлые» PDF. Сжатие с потерями (Ghostscript) — не в этом этапе.
- qpdf с кодом выхода 3 («есть предупреждения», например, починил битую таблицу xref) — успех: файл записан.
- «Один PDF» для картинок — 2+ картинки, каждая страницей (первый кадр, `-auto-orient`, JPEG-сжатие, прозрачность на белом), имя по первой: `фото (все).pdf`. Все картинки ImageMagick держит в памяти одновременно — для пачки больших фото это долго и много памяти.

## D21. ZIP — встроенный движок — принято
- Упаковка и распаковка — средствами .NET (System.IO.Compression), без 7-Zip.
- «В ZIP» подходит к любому файлу; выбранные файлы — в один архив. Имя: один файл — как файл (`photo.jpg` → `photo.zip`); несколько — по папке первого файла (`Отпуск\1.jpg`, `Отпуск\2.jpg` → `Отпуск.zip`, как «Добавить к "Отпуск.zip"» в 7-Zip; в корне диска — по первому файлу). Одинаковые имена из разных папок → `name (1).ext`. Имена записей — в UTF-8 с флагом UTF-8 (проводник Windows 10/11 показывает кириллицу правильно).
- Поэтому пункт «Конвертировать…» регистрируется для всех файлов (`HKCU\Software\Classes\*\shell\DropWheel.Convert`); старые ключи по расширениям удаляются при установке. Папки пока не регистрируются.
- «Распаковать» — в папку с именем архива (`photos.zip` → `photos`, занято → `photos (1)`). Архив целиком отклоняется, если в нём пути за пределы папки (`..`, абсолютные пути, буквы дисков — Zip Slip), записи с паролем, больше 100 000 записей или больше 20 ГБ после распаковки (константы в `ZipEngine`). Недопустимые в Windows символы в именах → `_`.
- Имена без флага UTF-8: если байты — корректный UTF-8 (macOS, Linux), читаем как UTF-8, иначе — как CP866 (старые архиваторы и «Сжатая папка» русской Windows).

## D-EXTRAS. Дополнительные конвертации: OCR, ICO, SVG/PSD/RAW, GIF → видео, субтитры, «В UTF-8» — принято
- **Текст (OCR)** — встроенное распознавание Windows (`Windows.Media.Ocr`, движок `OcrEngine` в приложении), без внешних программ. Только JPG/PNG/BMP/TIFF — их Windows открывает сама; HEIC/WebP/AVIF/RAW — сначала → PNG. GIF не берём: у него колесо и так заполнено (8 секторов), а текст в GIF — редкость. Язык: русский, если установлен (модель ru-RU читает и латиницу); если русская модель не нашла ни одной кириллической буквы, а английская есть — перечитываем английской (у неё лучше словарь для английского текста). Нет русского — языки профиля пользователя, иначе первый установленный. Картинка больше предела OCR (`OcrEngine.MaxImageDimension`, ~2600 px) уменьшается, прозрачный фон — на белый (иначе чёрный текст на прозрачном PNG не виден). Результат — `скан.txt`, UTF-8 с BOM, строка текста = строка файла. Пустая картинка — «Текст не найден». Нет ни одного языка OCR (Параметры → Время и язык → Язык) — пункт не показывается.
- **ICO (значок)** — картинка вписывается в прозрачный квадрат 256×256, в файле размеры 256, 128, 64, 48, 32, 16 (`-background none -resize 256x256 -gravity center -extent 256x256 -define icon:auto-resize=…`). Белым не заливается (это только для JPG/PDF). Маленькие картинки растягиваются до 256.
- **SVG, PSD, RAW** (CR2, CR3, NEF, ARW, DNG, RAF, ORF, RW2) — только на вход, читает ImageMagick 7 (RAW — через LibRaw внутри него). Все конвертации картинок доступны; инструменты «того же формата» дают JPG (свой формат ImageMagick не пишет). SVG растрируется в своём размере (ширина и высота из файла) — мелкий SVG даст маленькую картинку. У PSD берётся сведённое изображение (если файл сохранён без «Максимальной совместимости», его может не быть). RAW проявляется с настройками LibRaw по умолчанию, поворот из тега Orientation применяется один раз (проверено на синтетическом DNG).
- **D8 — анимированный GIF: реализовано как предложено.** Для `.gif` в колесе, кроме картинок, есть «MP4» (H.264, CRF из настроек, `+faststart`) и «WebM» (VP9, CRF 32 — у VP9 своя шкала, как у «Видео → WebM»). Без звука, размеры кадра приводятся к чётным, `yuv420p` — иначе не играют плееры и браузеры. Анимацию по числу кадров перед показом колеса не проверяем: это запуск программы на каждый файл до появления колеса. Статичный GIF даст видео из одного кадра (0,1 с) — безвредно. Прозрачные места GIF становятся цветом, записанным в палитре (обычно белым или чёрным).
- **Субтитры SRT** (инструмент для видео) — первая дорожка субтитров → `фильм.srt` **без пометки**: плееры (VLC, MPC) сами подхватывают субтитры с тем же именем рядом с видео. Нет субтитров — «В файле нет нужной дорожки…». Субтитры-картинки (DVD/Blu-ray: VobSub, PGS) в текст не переводятся — понятная ошибка; распознавать их — не в этом этапе.
- **В UTF-8** (инструмент, движок `TextEngine` в ядре — работает и в CLI) — для TXT, CSV, SRT, MD, INI, LOG, XML, JSON. Уже UTF-8 (с BOM или без, чистый ASCII тоже) — «Файл уже в UTF-8», файл не создаётся. UTF-16/UTF-32 с BOM — перекодируется. Иначе выбирается Windows-1251 или DOS-866: при чтении в правильной кодировке байты ≥ 0x80 похожи на русские буквы — считаем сумму частот букв в русском языке (о — 11 %, е — 8,5 % … ъ — 0,04 %), псевдографика DOS (┤╛░) — штраф; больше сумма — та кодировка, при равенстве — 1251. Для обычного текста работает надёжно, на 2–3 буквах может ошибиться. Текст считается русским: западноевропейская 1252 («café») прочитается как 1251. Нулевые байты без BOM — «Это не текст…». Результат — `заметки (UTF-8).txt`, UTF-8 с BOM (Excel по нему узнаёт UTF-8 в CSV); JSON — без BOM (RFC 8259, парсеры на нём спотыкаются); в XML объявление `encoding="windows-1251"` меняется на `utf-8`. Файлы больше 256 МБ не берём (читаются в память целиком).

## D-7ZIP. Архивы через 7-Zip, PDF → TXT, поворот PDF — принято
- **7-Zip** — внешняя утилита: `tools/7zip/7z.exe` + `7z.dll` (полная версия, в ней и RAR; урезанные 7za/7zr RAR не умеют). Windows-сборка — официальная, из релизов GitHub `ip7z/7zip`: `build/fetch-tools.ps1` скачивает `7zr.exe` и установщик `7zNNNN-x64.exe` и распаковывает установщик через `7zr.exe`, не запуская его (запасной путь — 7-Zip, установленный в системе); в `tools/7zip` остаются только `7z.exe`, `7z.dll`, `License.txt`. На Linux (тесты) — пакет `7zip`, команда `7z`.
- ZIP по-прежнему распаковывает встроенный ZipEngine (D21). «Распаковать» для 7z, RAR, TAR, GZ, TGZ, BZ2, XZ — 7-Zip: `x -y -bso0 -bsp1 -sccUTF-8 -o<временная папка> -pnopassword -- <архив>`. Папка — по имени архива без «.tar»: `фото.tar.gz` → `фото`, занято → `фото (1)`.
- `.tar.gz`, `.tgz`, `.tar.bz2`, `.tar.xz`: 7-Zip за один запуск снимает только сжатие и кладёт один `.tar`. Если после распаковки .gz/.tgz/.bz2/.xz в папке ровно один файл и это tar (подпись `ustar`), DropWheel распаковывает его вторым запуском, а сам `.tar` не оставляет (на время распаковки нужно место и под `.tar`, и под файлы). Обычный `.gz` с одним файлом (`заметка.txt.gz`) просто распаковывается.
- Пароль: `-p` с выдуманным паролем, чтобы 7-Zip не ждал ввода (и у всех утилит теперь пустой stdin). Архив с паролем → «Архив с паролем не поддерживается».
- Безопасность (проверено тестами на 7-Zip 23.01, Linux): `..` и абсолютные пути 7-Zip отрезает сам — файлы остаются внутри папки (`../evil.txt` → `evil.txt`, `/tmp/x` → `tmp/x`); символические и жёсткие ссылки за пределы папки не создаёт («Dangerous link path was ignored») и завершается с ошибкой → «Архив небезопасен: в нём ссылки за пределы папки». Распаковка идёт во временную папку; при любой ошибке она удаляется целиком. На Windows это поведение не проверено вручную — тест там проверяет только, что за пределы папки ничего не записано. Лимитов, как у ZIP (20 ГБ / 100 000 файлов), нет: заранее их не проверить; кончится место — «Закончилось место на диске».
- «В 7Z» — любые файлы, все выбранные в один архив: `a -t7z -mx=7 -bso0 -bsp1 -sccUTF-8 -spd -sse <архив> -- <файлы>`. Пути передаются полными, но 7-Zip хранит только имена файлов, без папок; имена — в Unicode (кириллица сохраняется). Имя архива — как у «В ZIP» (`ZipEngine.ArchiveName`). Одинаковые имена из разных папок 7-Zip не принимает → «В 7Z нельзя положить файлы с одинаковыми именами из разных папок» (ZIP такие переименовывает). `-spd` — `*` и `?` в именах не считаются масками; `-sse` — не удалось открыть файл → архив не создаётся. `--` — дальше только пути (имя на `-` или `@` не примется за ключ).
- Коды выхода 7-Zip: успех — только 0. Код 1 («предупреждения») — ошибка: при упаковке он значит, что какой-то файл не попал в архив.
- Прогресс: с `-bsp1` 7-Zip пишет « 43%» в stdout без перевода строки и стирает его символами `\b`; EngineRunner читает stdout 7-Zip кусками (SevenZipProgress). У `.tar.gz` — по половине шкалы на каждый запуск.
- RAR тестами не проверен: создать RAR здесь нечем (WinRAR платный). Распаковка RAR — через `7z.dll`.
- **PDF → TXT** («TXT (текст)») — `pdftotext` из той же сборки poppler, что и pdftoppm: `-layout -enc UTF-8`. `-layout` сохраняет колонки и отступы; `-enc UTF-8` обязателен — в Windows pdftotext по умолчанию пишет Latin-1, и кириллица пропала бы. Переводы строк в Windows — CRLF (по умолчанию). Если в результате нет ни одной буквы или цифры (у скана — только разрывы страниц), файл не создаётся: «В PDF нет текстового слоя (это скан)» — для сканов нужно распознавание текста (OCR). Автор PDF запретил копирование текста → «Автор PDF запретил копировать из него текст».
- **Повернуть ↻** — `qpdf --rotate=+90`: все страницы на 90° по часовой стрелке без перекодирования (меняется только `/Rotate` страниц). Повторный поворот добавляет ещё 90°. Имя: `тест 1 (повёрнуто).pdf`.

## D-OFFICE. Документы через установленный Microsoft Office — принято
- **Office не работает — запасной движок** (1.1.1). Если Office есть, но конвертация упала (не активирован, окно первого запуска, файл не открылся — у друга Романа Word 2013 падал на всех .docx с 0x800A1066), а у операции есть `Fallback` (WebPdf, DocLibs) — `Converter.RunEngineAsync` повторяет запасным движком (с 1.3.0 сначала — установленным LibreOffice, D-LIBREOFFICE); ошибка пароля — не повод. Перед этим Office сам пробует чистую копию файла (защищённый просмотр для файлов «из интернета»).
- **Что.** DOC/DOCX/DOCM/RTF/ODT → PDF, DOCX, DOC, ODT, RTF, TXT (UTF-8); XLS/XLSX/XLSM/ODS/CSV → PDF (вся книга), XLSX, XLS, CSV, ODS; PPT/PPTX/PPTM/ODP → PDF, PPTX, PPT, ODP, «Слайды PNG» (папка `доклад (слайды)`, `слайд-1.png`…, 1920 px по ширине); PDF → DOCX (Word сам перестраивает PDF). Конвертация в тот же формат не предлагается. Делает сам Office через COM (`OfficeEngine`, позднее связывание — работает с любой версией 2013+, без сборок взаимодействия). Таблица «операция → приложение и код формата» — `OfficeFormats` в ядре (проверяется тестами на Linux).
- **Только если Office установлен.** Наличие Word / Excel / PowerPoint проверяется по реестру (ProgID), отдельно для каждого, один раз; Office при этом не запускается. Нет приложения — его операций нет в колесе (кроме тех, у которых есть запасной движок: Word → PDF через Edge, Word → TXT и Excel → CSV через библиотеки).
- **Скорость.** Office запускается долго: первый документ «с холода» — около 3–5 с, следующие — около 1 с. Поэтому, как только колесо или меню показали операции Office, нужное приложение запускается заранее невидимым («прогрев»), пока пользователь выбирает сектор, — к броску оно обычно уже готово. Запущенное приложение живёт, пока им пользуются, и закрывается через 5 минут простоя (`OfficeEngine.IdleTimeout`); при выходе из DropWheel закрывается всё, что мы запустили. Цена — память: прогретый Word или Excel занимает примерно 100–200 МБ, пока не закроется.
- **Свой отдельный экземпляр.** Всегда новый невидимый экземпляр (`CreateInstance`, никогда «подключиться к открытому»): окна и несохранённые документы пользователя не трогаем, а наш экземпляр можно спокойно закрыть или убить. Если пользователь открыл свой файл в нашем скрытом Word (двойной щелчок в проводнике иногда отдаёт файл уже запущенному Word), экземпляр оставляем ему и запускаем новый. PowerPoint — исключение: он бывает только в одном экземпляре; если он уже открыт пользователем, работаем в нём осторожно: без окон, никогда не закрываем и не убиваем, настройки меняем только на время задачи, файл, открытый у пользователя, не трогаем («закройте его и повторите»).
- **Безопасно и без вопросов.** Файлы открываются только для чтения, не попадают в «последние файлы», закрываются без сохранения (и при ошибке тоже). Макросы в открываемых файлах запрещены (`AutomationSecurity = ForceDisable`), связи с другими файлами не обновляются, все вопросы Office отключены. Документ с паролем: DOCX/XLSX/PPTX узнаём ещё до Office (это зашифрованный составной файл), для DOC/XLS Office получает пароль-заглушку и отвечает ошибкой — в обоих случаях «Документ защищён паролем», без невидимого окна с вопросом пароля.
- **Не зависнуть.** Все вызовы Office — в одном отдельном потоке со своей очередью, документы идут по одному. Если Office занят, вызов повторяется (фильтр сообщений COM, до 30 с). Конвертация дольше 2 минут (PDF → DOCX и слайды — 5) или отмена — процесс Office, который мы запустили, завершается, задача — с ошибкой, следующая запустит Office заново. Закрыли Word сами или он упал — следующий документ просто запустит новый.
- **Word и PDF.** Открывая PDF, Word спрашивает «Word преобразует PDF в редактируемый документ…». Отключаем вопрос так же, как галочка «Больше не показывать»: `HKCU\Software\Microsoft\Office\<версия>\Word\Options`, `DisableConvertPdfWarning = 1` (версия — у запущенного Word, обычно 16.0). Это настройка пользователя; возвращать её не нужно — при открытии PDF вручную вопрос тоже пропадёт.
- **CSV из Excel.** Сохраняется первый лист, в UTF-8, с разделителем из региональных настроек Windows (у русской — «;»), как при «Сохранить как» в самом Excel; CSV на входе читается так же. Excel старше 2016 без «CSV UTF-8» — CSV в кодировке Windows.
- **PDF → Markdown** (`pdf-to-md`, «Markdown» в колесе PDF, 5-й лепесток «Конвертации» из 8). С Word: Word сохраняет PDF во временный DOCX (в той же скрытой папке `.dropwheel-tmp`, удаляется сразу), из него Markdown делает та же библиотека, что и Word → Markdown (`DocxText.ToMarkdown`): заголовки, списки, жирный, таблицы — насколько их распознал Word. Без Word — запасной движок pdftotext (`Fallback`): текст с колонками как есть, без разметки; у скана — то же сообщение, что у PDF → TXT. Таймаут — как у PDF → DOCX (5 мин).
- **«MD (быстро)»** (`pdf-to-md-fast`, по просьбе Романа: через Word долго) — `pdftotext -enc UTF-8` без `-layout` (абзацы в порядке чтения) в `.md`, мгновенно, без разметки. У «Markdown» через Word запасного движка больше нет: без Word лепесток не показывается, есть только быстрый.
- **Ограничения.** Старая PPT с паролем может вызвать невидимый вопрос пароля — задачу снимет таймаут. Если DropWheel упадёт (а не выйдет), запущенный им скрытый Office останется до выхода из Windows — его можно закрыть в диспетчере задач.

## D-DOCLIBS. Документы без Office: бесплатные библиотеки и печать в PDF через Edge — принято
- **Зачем.** Office есть не у всех. Без него работают запасные движки для операций D-OFFICE (поле `Fallback`): Word → PDF — Edge (`WebPdfEngine`), Word → TXT и Excel → CSV — библиотеки (`DocLibsEngine`). Свои операции (блок `DOCLIBS` в каталоге): Word → HTML и Markdown, CSV → XLSX, Markdown → HTML, «PDF» для TXT / Markdown / HTML. Word без Office — **только DOCX/DOCM**: DOC, RTF и ODT библиотеки не читают, для них без Office эти операции не предлагаются (движок отвечает по расширению — `CanRun(op, ext)`). Excel без Office — XLSX, XLSM, XLS (ODS — нет).
- **Библиотеки** (все бесплатные, с разрешающими лицензиями; лежат в ядре — работают и в CLI, и в тестах на Linux): `DocumentFormat.OpenXml` 3.5.1 (Open XML SDK, MIT) — чтение DOCX, запись XLSX; `Codeuctivity.OpenXmlPowerTools` 9.0.493 (MIT; последняя версия под .NET 8) — DOCX → HTML, тянет `SkiaSharp` 3.119.2 (MIT; внутри Skia — BSD-3-Clause; отладочные символы родной libSkiaSharp — 83 МБ — из сборки исключены в `Directory.Build.props`); `ExcelDataReader` 3.9.0 (MIT) — чтение XLSX/XLS (кодовые страницы для XLS — встроенный в .NET `CodePagesEncodingProvider`); `ExcelNumberFormat` 1.1.0 (MIT) — числа и даты «как в ячейке Excel»; `Markdig` 1.3.2 (BSD-2-Clause) — Markdown → HTML. В приложении — `Microsoft.Web.WebView2` 1.0.4258.31 (BSD-3-Clause), сам Edge WebView2 Runtime — часть Windows 10/11. Версии — не новее двух недель на момент выбора. ClosedXML не взят: для записи простого XLSX хватает Open XML SDK, а ClosedXML тянет ещё пять пакетов.
- **Edge (WebPdfEngine, только приложение).** HTML → PDF через `CoreWebView2.PrintToPdfAsync`: фон печатается, колонтитулов браузера (адрес, дата) нет. Доступен, если установлен WebView2 Runtime (`GetAvailableBrowserVersionString`); нет — «PDF» для текста и Word → PDF без Office не предлагаются. Edge живёт в невидимом окне на потоке интерфейса (WebView2 нужен STA с циклом сообщений), профиль — `%LocalAppData%\DropWheel\WebView2`; один на приложение, запускается заранее, когда колесо/меню показали его операции (`Prepare`), или при первой печати; закрывается через 2 минуты простоя и при выходе. Поток интерфейса не блокируется: вся работа — асинхронно через `Dispatcher`. Задачи печатаются по одной; на задачу — 60 с, иначе ошибка, и Edge создаётся заново; страница, которая грузится дольше 30 с (ждёт сеть), печатается как есть. HTML-файл открывается сам по `file:///` (относительные картинки и стили грузятся, скрипты страницы работают; всплывающие окна, загрузки и `alert` подавлены). TXT (моноширинный шрифт, переносы длинных строк, HTML-экранирование) и Markdown — через временную страницу в `%TEMP%\DropWheel\pdf`; у Markdown — `<base>` на папку исходника, чтобы нашлись картинки. Лист для текста — A4, поля 18 мм. PDF пишется во временную папку и потом переносится — если Edge «зависнет», мусора рядом с исходником не будет.
- **Точно или «почти».** Данные (CSV ↔ XLSX), текст DOCX → TXT/Markdown и Markdown → HTML — точно. **DOCX → HTML и DOCX → PDF через Edge — «почти как в Word»:** шрифты и размеры, жирный/курсив/цвет, отступы и интервалы, списки с номерами, таблицы (объединённые ячейки, рамки, заливка), картинки (внутри HTML, `data:`), размер листа и поля из документа (CSS `@page` и настройки печати), разрывы страниц, «с новой страницы» (в т. ч. из стиля — заголовки по ГОСТу), разрывы разделов. Строки и страницы разбивает браузер, а не Word, — страницы могут разойтись на строку-другую. **Не переносятся:** колонтитулы и номера страниц, сноски, примечания, надписи, фигуры, SmartArt, диаграммы, картинки EMF/WMF (старые вставки — пустое место), колонки, разный размер листа в разделах (берётся первый раздел). Нужно точно — Office.
- **DOCX → TXT:** UTF-8 с BOM, CRLF; абзац — строка (пустые абзацы сохраняются); номера списков как в Word (`1.`, `1.1.`, `а)`, маркер — `•`), вложенность — 4 пробела; таблица: строка — строка, ячейки через Tab; текст надписей — после абзаца; колонтитулы, сноски, удалённый при рецензировании текст не берутся.
- **DOCX → Markdown:** UTF-8 без BOM; заголовки — по стилю «heading N» (так внутри называются и «Заголовок N» русского Word, у которых id стиля «1», «2»…) или уровню структуры, «Title» → `#`; жирный, курсив, зачёркнутый, ссылки, вложенные списки, таблицы GFM (первая строка — шапка, абзацы ячейки — через `<br>`, `|` экранируется; таблица из одной ячейки — просто текст). Спецсимволы Markdown экранируются, абзац «1. Набрано вручную» остаётся абзацем (`1\.`). Картинки не переносятся — пометка `*[Рисунок: описание]*` (нужны картинки — «HTML»).
- **Excel → CSV без Office** — как «Сохранить как → CSV» в Excel и как OfficeEngine (`Local:=True`): первый видимый лист; разделитель — «разделитель элементов списка» из региональных настроек Windows (`CultureInfo.CurrentCulture.TextInfo.ListSeparator`; у русской Windows — «;», пусто — «;»); значения — как показаны в ячейках, по их формату и региональным настройкам: `1234,5`, `15%`, `1 234,50 ₽`; встроенные форматы дат 14 и 22 — короткая дата Windows (`15.03.2023`, `15.03.2023 18:00`); ИСТИНА/ЛОЖЬ и ошибки (`#ДЕЛ/0!`) — по-русски на русской Windows; у формул — последние сохранённые значения. **UTF-8 с BOM** — так русский Excel открывает файл двойным щелчком без «кракозябр» и сразу по столбцам (строку `sep=;` не пишем: с ней Excel перестаёт замечать BOM). Строки — CRLF, поле в кавычках, только если в нём разделитель, кавычка или перевод строки. Пустые строки и столбцы в конце отрезаются.
- **CSV → XLSX** (и с Office тоже — «→ XLSX» у Office CSV не берёт, чтобы в колесе не было двух «XLSX»: библиотеки здесь надёжнее Excel). Кодировка: BOM (UTF-8 / UTF-16), иначе корректный UTF-8, иначе Windows-1251. Разделитель «;», «,» или Tab — тот, при котором первые 50 строк делятся на одинаковое число полей (≥ 2, кавычки учитываются); поровну — «;», потом Tab, потом «,». Числа → числа Excel (`1234,5`, `1234.5`, `1 234 567,89`; десятичная запятая — только если разделитель не «,»), `15%` → 0,15 в процентах, даты `дд.мм.гггг` и `гггг-мм-дд` (с временем) → даты. Текстом остаются коды с ведущими нулями (`007`), `+7…`, больше 15 цифр, всё, что начинается с `=`: формулы из CSV не создаются никогда (защита от «CSV-инъекций»). Ширина столбцов — по самому длинному значению (8…60 символов), лист — по имени файла. Больше 1 048 576 строк или 16 384 столбцов — ошибка.
- **Markdown → HTML:** Markdig с расширениями (таблицы, списки задач, сноски, автоссылки, зачёркивание), стили внутри страницы (в духе GitHub, годятся для печати); кодировка исходника угадывается (UTF-8 / 1251); HTML внутри Markdown пропускается как есть.

## D-LIBREOFFICE. Документы через установленный LibreOffice — принято
- **Зачем.** Microsoft Office есть не у всех (или не активирован, падает). Бесплатный LibreOffice открывает DOC, RTF, ODT, XLS, ODS, PPT — то, что без Office не умеют ни библиотеки, ни Edge. Не встраиваем (~350 МБ) — находим установленный.
- **Где ищем** (`LibreOfficeLocator`, один раз за время работы): переменная `DROPWHEEL_SOFFICE` → реестр `HKLM\SOFTWARE\LibreOffice\UNO\InstallPath` (и `WOW6432Node` для 32-битного) → `C:\Program Files\LibreOffice\program` (и `Program Files (x86)`) → в Linux PATH. В папке — `soffice.com` (консольный, ждёт конца конвертации), иначе `soffice.exe`. Настройки в окне нет.
- **Порядок движков** для операций Office (`Converter.Candidates`): Microsoft Office (если установлен) → LibreOffice (если есть и умеет операцию) → запасной движок операции (`Fallback`: Edge, библиотеки). Упал один — пробуем следующий (кроме ошибки пароля); ошибка — от последнего. В колесе операции Office есть, если её может выполнить хотя бы один.
- **Что умеет** (таблица `LibreOfficeFormats`, проверяется тестами): Word (DOC/DOCX/DOCM/RTF/ODT) → PDF, DOCX, DOC, ODT, RTF, TXT (UTF-8 с BOM, CRLF — как у Word); Excel (XLS/XLSX/XLSM/ODS) → PDF (вся книга), XLSX, XLS, CSV, ODS; PowerPoint (PPT/PPTX/PPTM/ODP) → PDF, PPTX, PPT, ODP. Не умеет у нас: «Слайды PNG» (LibreOffice пишет только первый слайд), PDF → DOCX / Markdown (плохо перестраивает PDF), CSV на входе (читал бы со своими настройками; CSV → XLSX — библиотеки).
- **CSV** — как у Excel и библиотек: первый **видимый** лист (номер находим сами — LibreOffice иначе берёт первый, даже скрытый), UTF-8 с BOM (BOM дописываем сами), разделитель — из региональных настроек Windows (у русской «;»), значения — как показаны в ячейках.
- **Запуск:** `soffice -env:UserInstallation=<URL> --headless --norestore --nologo --nodefault --nolockcheck --convert-to <фильтр> --outdir <папка> <файл>`, аргументы — через `ArgumentList`. На каждую задачу — свой временный профиль и папка результата в `%TEMP%\dropwheel-lo-<guid>` (удаляются сразу): не мешаем открытому LibreOffice пользователя, нет окон первого запуска, две задачи идут параллельно. Путь профиля — URL с %-кодированием UTF-8 (`C:\Users\Роман` → `file:///C:/Users/%D0%A0…`). Готовый `<имя>.<расширение>` переносится во временный файл DropWheel — дальше как у всех (свободное имя, исходник не трогаем).
- **Ошибки.** soffice при неоткрываемом файле пишет «Error: source file could not be loaded» и выходит с кодом 0 — успех проверяем по файлу результата: нет — «LibreOffice не смог сконвертировать файл». Таймаут 3 минуты — процесс убивается вместе с `soffice.bin`: «LibreOffice не ответил за 3 мин — остановлен». Документ с паролем (DOCX/XLSX/PPTX) узнаём заранее — «Документ защищён паролем».
- **Скорость.** Каждый файл — новый запуск с пустым профилем: несколько секунд (в Linux ~3 с). Прогрева нет.
- **Linux (тесты).** С языком «C/POSIX» soffice зависает на пути профиля с кириллицей — процессу задаём `LC_ALL=C.UTF-8`. Интеграционные тесты с настоящим LibreOffice пропускаются, если его нет (CI).

## D-UX. Внешний вид: колесо, окно задач, уведомления, значок — принято
Цель — «не хуже, чем на macOS»: стекло, мягкие анимации, системные тема и акцент. Колесо — в стиле Windows 11. Всё необязательное — с запасным вариантом; поломка эффекта не ломает перетаскивание.
- **Тема и акцент.** Светлая/тёмная — из реестра (`AppsUseLightTheme` для колеса, `SystemUsesLightTheme` для окна задач и меню трея — как у системных всплывающих окон), акцент — `UISettings`; перечитываются при смене настроек Windows (`SystemEvents.UserPreferenceChanged`). Шрифт — Segoe UI Variable, только если WPF видит у него настоящие Regular/SemiBold, иначе Segoe UI. Значки — Segoe Fluent Icons (Windows 11) или Segoe MDL2 Assets (Windows 10), коды общие.
- **Анимации** уважают «Эффекты анимации» Windows (`SystemParameters.ClientAreaAnimation` и `UISettings.AnimationsEnabled`): выключены — всё мгновенно. `DROPWHEEL_NO_ANIMATIONS=1` выключает их принудительно; скриншот-тесты — `Motion.ForceDisabled`.
- **Колесо.** Диск 288 DIP, отдельные скруглённые «лепестки» с зазорами 5 px, центр ~42 % с «пилюлей»: размер перетаскиваемых файлов («1,1 МБ»), имя лепестка под курсором или «Отмена». Конвертация — названия форматов прописными без значков (уточнение в скобках — мелко ниже), инструменты — значок над подписью; значок подбирается по id операции, расширению результата и типу файла (`OperationGlyphs`, каталог не трогаем). Наведение — заливка акцентом за 90 мс (гаснет за 120), лепесток чуть «приподнимается». Открытие «вырастает» из точки курсора 0.3 → 1.03 → 1 (~270 мс), смена режима — поворот с проявлением, бросок на лепесток — вспышка и закрытие за 110 мс.
- **Стекло колеса.** Слоистое окно (`AllowsTransparency`, как и раньше — ради перетаскивания) + акриловое размытие `SetWindowCompositionAttribute` + круглая форма окна `SetWindowRgn` (форма следует за анимацией). Тень круглая форма обрезала бы — её рисует отдельное окно под колесом, прозрачное для мыши и перетаскивания (`WS_EX_TRANSPARENT`). Без «Эффектов прозрачности», при высокой контрастности, если форма не встала или `DROPWHEEL_EFFECTS=0` — плотный диск с тенью в одном окне. Под диском — подложка с альфой 1/255 без анимации, чтобы окно было целью перетаскивания с первого кадра.
- **«Конвертировать…» из проводника** — то же колесо в режиме клика (см. D16); запасной вариант — старое списочное меню.
- **Окно задач у трея** — как всплывающие окна Windows 11: `WindowChrome` без рамки (тень и скругление от системы), `DWMWA_WINDOW_CORNER_PREFERENCE` (Windows 11), акриловая подложка `DWMWA_SYSTEMBACKDROP_TYPE` (Windows 11 22H2+; иначе сплошной фон темы), место — у области уведомлений на мониторе курсора, панель задач у любого края, в том числе автоскрытие (`TrayFlyoutPlacement`, с тестами). Миниатюры — `IShellItemImageFactory` в отдельном STA-потоке; нет миниатюры — значок типа, нет и его — значок шрифта.
- **Уведомления.** Превью результата (фото/видео — из миниатюры проводника, JPEG 2:1 во временной папке, хранится 2 дня), «Открыть» и «Показать в папке». Задачи, закончившиеся в пределах ~1 с (но не дольше 3 с ожидания), — одно уведомление «Готово: N файлов», кнопка выделяет все файлы в папке. Ошибки — «Подробнее» открывает журнал.
- **Значок.** Кольцо из четырёх плиток, как сектора колеса, верхняя правая — тёплая и приподнята: `docs/assets/icon.svg` (32 px и больше) и упрощённый под пиксельную сетку `icon-small.svg` (16–24 px) → `src/DropWheel/Assets/DropWheel.ico` (16…256 px), пересборка — `build/make-icon.sh`. В трее — этот значок, в работе — с оранжевым кружком-счётчиком. Меню трея — в цветах темы (WinForms, свой отрисовщик).
- **Проверка.** Скриншот-тесты (`tests/DropWheel.Windows.Tests`, артефакт CI `screenshots`) — колесо во всех состояниях и обеих темах, окно задач, значки. Как это выглядит и ощущается на живой Windows — чек-лист «UX» в `manual-tests.md`.

## D22. Пробел «перестаёт реагировать» — защита — принято
Две причины, обе закрыты:
1. **Потерянное отпускание клавиши.** Если Пробел отпустили там, куда хук не видит (экран блокировки, окно UAC, окно программы от администратора), детектор считал его «зажатым» и все следующие нажатия — автоповтором. Теперь нажатие позже чем через 1,5 с после предыдущего — новое нажатие (`DragDetector.StaleKeyMs`); после разблокировки и сна состояние клавиш сбрасывается.
2. **Windows молча снимает low-level хук**, если обработчик хоть раз не уложился в таймаут (нагрузка, выход из сна). Страж раз в 5 с сравнивает время последнего ввода в системе (`GetLastInputInfo`) с последним событием, дошедшим до хуков; разрыв > 3 с — хуки переустанавливаются (не чаще раза в 30 с, запись в журнал). Также переустановка при разблокировке экрана и выходе из сна.

## D-SETTINGS. Окно настроек и своё колесо — принято
- **Что.** Окно «Настройки DropWheel» (этап 4, раздел 10 ТЗ): горячая клавиша, куда класть результат, качество (JPG/WebP 50–100, CRF видео 18–32, MP3 128–320 кбит/с), автозапуск, пункт в проводнике, проверка обновлений; раздел «Колесо» — свой порядок и видимость лепестков по типам файлов и «последний выбор — первым». Открывается пунктом трея «Настройки…» и двойным кликом по значку; одно на приложение. Пути к ffmpeg/magick в окне не показываем (раздел 10 ТЗ): нужны только для разработки — остаются в settings.json.
- **Без «ОК/Отмена».** Как «Параметры» Windows 11: всё применяется сразу. Единая точка — `App.UpdateSettings`: горячая клавиша — в работающих хуках (`DragWheelController.Hotkey`), качество и папка — `Converter.Settings` (меняется атомарно; каждая конвертация читает настройки один раз в начале, поэтому идущие задачи доделываются со старыми, новые берут новые), пункт проводника, автозапуск, обновления; трей и окно показывают одно и то же. settings.json пишется через 0,6 с после последней правки (`SettingsSaver`), при закрытии окна и выходе — сразу.
- **Автозапуск** — значение `DropWheel` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` = `"<exe>" --autostart`; с этим ключом подсказка «DropWheel работает» не показывается. Правда — реестр, а не settings.json (запись могли выключить в «Диспетчере задач → Автозагрузка»): при запуске и при открытии окна переключатель читается из реестра. Программу перенесли в другую папку, а старого exe уже нет — запись переписывается на новый путь; если старый exe на месте (вторая копия) — не трогаем.
- **Своё колесо.** Типы: фото, видео, звук, PDF, Word, Excel, PowerPoint, текст, архивы, «любые файлы» (`WheelGroups`; файлы разных типов вместе — «любые»). Для каждого типа и режима хранится полный порядок id и скрытые id (`WheelPreferences` в settings.json, ключ `wheel`); старый settings.json без него читается как «всё по умолчанию». Раскладка (`WheelArrangement.Arrange`, одна функция для перетаскивания и меню проводника): операции, доступные этим файлам на этом компьютере, → сохранённый порядок (новые операции, которых в нём нет, — в конец, в порядке каталога) → без скрытых → «последний выбор» наверх (если включено; скрытый не показывается) → не больше 8. Последний выбор хранится по типу и режиму и запоминается при любом выборе (колесо, меню проводника). Скрыть все форматы одного режима можно; если скрыто всё в обоих режимах — показывается обычный порядок, чтобы колесо для поддерживаемого файла не было пустым. «Последний — первым» по умолчанию выключено: колесо не «прыгает», пока пользователь сам этого не захочет.
- **Список в настройках** показывает все операции каталога для типа (с пометками «только CSV», «от 2 файлов», «нужен Microsoft Office»; восьмой и дальше — «не виден»); мини-колесо справа — тот же `WheelControl`, что и настоящее. Порядок — перетаскиванием строки или кнопками ↑/↓.
- **Вид.** Обычное окно с системным заголовком; Windows 11 22H2+ — подложка Mica (`DWMWA_SYSTEMBACKDROP_TYPE = 2` + «стекло» на всё окно), иначе сплошной фон темы. Тема — как у приложений Windows (`AppsUseLightTheme`), акцент — системный, Segoe UI Variable. Элементы (переключатели, ползунки, «пилюли» выбора, флажки) нарисованы в коде в стиле Windows 11, без шаблонов WPF.
- **Строки** интерфейса — в ядре, `DropWheel.Core/Localization/Texts*.cs`; `src/DropWheel/Ui/Strings.cs` — короткие имена для окна настроек (см. D-LANG).
- **Проверка.** Ядро — юнит-тесты (порядок, скрытые, новые операции, запасной вариант, «последний», чтение старого settings.json, отложенная запись, автозапуск). Вид — скриншот-тесты `SettingsScreenshots` (ветка `screenshots`). На Windows — чек-лист «Этап 4 — настройки» в `manual-tests.md`.

## D-LANG. Интерфейс на русском и английском — принято
- **Какой язык.** Настройка `language` в settings.json: `auto` (по умолчанию), `ru`, `en`; в окне настроек — «Основное → Язык интерфейса»: «Как в Windows / Русский / English». `auto` смотрит на язык интерфейса Windows (`CultureInfo.CurrentUICulture`): русский — только для русской Windows (`ru-*`), всем остальным, включая украинскую, белорусскую и казахскую, — английский (у английского шире аудитория, а русский в таких системах всегда можно выбрать вручную). Неизвестное значение в settings.json читается как `auto`.
- **Как устроено.** Ядро (`DropWheel.Localization`): `Loc.Current` — текущий язык (по умолчанию русский: ядро и тесты не зависят от языка машины; язык выбирают точки входа — DropWheel.exe по настройке, CLI по языку системы или `--lang ru|en`). Строки — `Texts` (свойство = ключ; русское значение по умолчанию в `Texts.cs`, английское — в `Texts.En.cs`); шаблоны с `{0}` — через `Loc.F`. Склонение — `Noun` (по-русски три формы, по-английски две), размер — `Loc.FileSize` («1,1 МБ» / «1.1 MB»). Без .resx: одна таблица в коде проще, её полноту проверяет тест.
- **Операции.** Каталог хранит id и русскую подпись/пометку (как раньше); показ — через `Loc.Label(op)` / `Loc.Suffix(op)`: английские подписи (не длиннее 16 символов) и пометки — в `OperationTexts`, названия форматов одинаковы. Имена результатов тоже на языке интерфейса: `photo (compressed).jpg`, папка `report (pages)` с `page-1.png`, слайды `slide-1.png` (`{page}` в шаблоне аргументов). Русским пользователям всё как было.
- **Ошибки.** Причины из `ErrorTranslator` и все `ConversionException` (ядро, Office, Edge, OCR) — из `Texts`. Журнал остаётся по-русски: его читают при разборе ошибок.
- **Смена на лету.** `App.ApplyLanguage`: трей переписывает пункты, окно настроек и окно задач перестраиваются, пункт меню проводника перерегистрируется с новой подписью; колесо, уведомления и новые задачи берут язык в момент показа. Имя результата выбирается в начале конвертации — на языке, который действует в этот момент.
- **Демо-ролик** записывается с `"language": "ru"` — при любом языке Windows на раннере CI.
- **Проверка.** `LocalizationTests`: у каждой строки и слова есть английский вариант (без кириллицы, с теми же подстановками), подписи всех операций на обоих языках, склонение, размеры, выбор языка; `EnglishTests` — имена результатов, ошибки, CLI `--lang`; тесты, меняющие язык, — в отдельной непараллельной коллекции. Windows: `EnglishScreenshots` — колесо, окно задач, настройки на английском (`*-en-*.png` в ветке `screenshots`). На Windows — пункт 10 чек-листа «Этап 4».

## D-CLIPBOARD. Колесо для буфера обмена и видео-инструменты — принято
- **Что.** Пункт трея «Из буфера обмена…» и глобальное сочетание <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>V</kbd> (настройка `clipboardHotkey`, по умолчанию включена; «Основное → Windows»). В буфере файлы (CF_HDROP, «Копировать» в проводнике) — колесо у курсора в режиме клика для них, как из меню проводника. Нет файлов, но есть картинка (формат «PNG» — байт в байт, с прозрачностью; иначе Bitmap/DIB → PNG) — она сохраняется в `Буфер 2026-10-22 10-31-05.png` / `Clipboard ….png` и открывается колесо для неё. Остальное (текст, пусто) — подсказка в трее «В буфере нет картинки или файлов»; в .txt текст не превращаем.
- **Куда кладётся картинка.** В общую папку для результатов, если в настройках выбрано «В одну папку», иначе — `%USERPROFILE%\Pictures\DropWheel` («Изображения\DropWheel»): буфер — не файл, «рядом с исходником» не бывает, а «Изображения» — привычное место для снимков экрана. Результат конвертации ложится туда же (рядом с PNG). Имя занято — `… (1).png`.
- **Настройки картинки** («Основное → Windows», по просьбе Романа). «Картинки из буфера обмена»: «По умолчанию» (как выше) или «Своя папка» (`clipboardFolder`; своя папка важнее «одной папки»). «Оставлять исходную картинку» (`keepClipboardImage`, по умолчанию включено): если выключить, PNG удаляется после **удачной** конвертации, когда результат — другой файл. Ошибка, отмена задачи или закрытое без выбора колесо — PNG остаётся, чтобы картинка не пропала. Это единственное исключение из правила «исходник не удаляется»: PNG создала сама программа, пользователь его не сохранял. Удаляются только PNG, сохранённые в этом сеансе программы (список в памяти).
- **Файлы важнее картинки**; берутся только существующие файлы (не папки, без повторов). Логика — в ядре (`Shell/ClipboardPlan`, юнит-тесты), чтение буфера — `Shell/ClipboardReader` (WinForms Clipboard в потоке UI; буфер занят — 5 попыток через 100 мс, не вышло — «Не удалось прочитать буфер обмена»).
- **Сочетание** — `RegisterHotKey` на скрытом окне-приёмнике (HWND_MESSAGE) в потоке UI (`Input/GlobalHotkey`), с `MOD_NOREPEAT`. Занято другой программой — запись в журнал, работаем без него (пункт трея остаётся). Выключили в настройках — `UnregisterHotKey` сразу. Хуки клавиатуры для этого не нужны.
- **Видео.** «Повернуть ↻» (`video-rotate-cw`, инструмент): `transpose=1` + чётный размер, H.264 как у «Сжать», но с CRF из настроек; звук — AAC, а не copy: PCM/FLAC из MOV/MKV в MP4 не кладётся, а условий в шаблоне каталога нет. Пометка поворота с телефона применяется ffmpeg до transpose. «Кадры» (`video-frames`, инструмент, результат — папка `видео (кадры)`): `fps=1`, не больше 300, `кадр-001.jpg`… (`{frame}` — «кадр» / «frame»). У ffmpeg результат дописывается последним аргументом, если в шаблоне нет `{out}`; с `{out}` — подставляется в шаблон, а `%` в пути удваивается (иначе папка «100% отпуск» ломает шаблон номера кадра). «JPG (кадр)» (`video-poster`) — в режиме «Конвертация», а не «Инструменты»: инструментов у видео уже 8 (лимит колеса); кадр на 1-й секунде, `tpad` клонирует последний кадр на секунду, поэтому ролик короче секунды тоже даёт обложку.
- **Проверка.** `ClipboardPlanTests` (выбор действия, имя файла, папка), `VideoToolsTests` (аргументы, `%` в пути, подписи), интеграционные `VideoToolsConversionTests` (поворот меняет ширину и высоту, 3 с → 3 кадра, обложка, исходник не тронут, временных файлов нет). На Windows — раздел «Буфер обмена и видео» в `manual-tests.md`.

## D-OPACITY. Прозрачность колеса — принято
- **Что.** Настройка `wheelOpacity` (плотность заливки, %, 40–100; по умолчанию 88 — исходный вид: плотный диск был с альфой 0xE0 ≈ 88 %). Вне диапазона (руками в settings.json) — приводится к границе; старый settings.json без поля — 88.
- **Как.** Альфа заливок диска (`DiscSolid`, `DiscTint`), лепестков (`Petal`), центра (`Center`) и пустого кольца (`Track`) умножается на `percent / 88` (`WheelFill.ScaleAlpha`, ядро, юнит-тесты): при 88 — ровно как было, при 100 — диск непрозрачный. Подписи, значки, кромки, пилюля и акцентная заливка наведённого лепестка не меняются — читаемость важнее. `WheelPalette.WithFill` (кэш последнего варианта) + свойство `WheelControl.FillPercent`.
- **Где.** «Основное → Прозрачность колеса»: ползунок «плотнее ↔ прозрачнее» (вправо — прозрачнее) и мини-колесо на полосатой подложке, чтобы было видно, как оно просвечивает. Применяется сразу (`App.UpdateSettings`): колесо при перетаскивании, колесо из меню проводника / буфера обмена, мини-колесо на вкладке «Колесо».
- **Проверка.** `WheelFillTests`, `AppSettingsTests` (сохранение, старый файл, границы); скриншоты `wheel-{light,dark}-opacity-50`; пункт 11 «Этапа 4» в `manual-tests.md`.

## D-FOLDERS. Папки целиком — принято
- **Что.** Правый клик по папке → «Конвертировать…» (тот же пункт, что у файлов) → то же колесо в режиме клика (D16) с операциями для файлов внутри → результаты в папку рядом: `Отпуск` → `Отпуск (JPG)` (по-английски — `Vacation (JPG)`). Исходники не меняются и не удаляются. Перетаскивание папки + Пробел — то же колесо (операции по содержимому), бросок на сектор — то же самое.
- **Реестр.** Второй ключ `HKCU\Software\Classes\Directory\shell\DropWheel.Convert` — те же значения, что у `*\shell\…` (`MUIVerb`, `Icon`, `MultiSelectModel=Player`, `command` = `"<exe>" --convert "%1"`). Фон папки (`Directory\Background`) и диски (`Drive`) не регистрируем: «конвертировать весь диск» — почти всегда ошибка. `--unregister`, выключатель в настройках и деинсталлятор (`FolderMenuKey` в `DropWheel.iss`) удаляют и его. `CommandLine` принимает пути папок наравне с файлами.
- **Что внутри** (`Jobs/FolderPlan.Scan`, ядро). С подпапками, в порядке проводника (файлы папки — «фото 2» раньше «фото 10», затем подпапки). Пропускаются скрытые и системные файлы и папки (`desktop.ini`, `Thumbs.db`, `.git`), наша `.dropwheel-tmp` и недописанные `.dropwheel-*`, ссылки на папки (symlink/junction — защита от петли; «облачные» папки OneDrive ссылками не считаются), глубже 32 уровней не идём. Нет доступа к подпапке — она пропускается. Больше 1000 файлов (`FolderPlan.MaxFiles`) — не берём совсем, подсказка в трее «выберите папку поменьше»: обработать «первые 1000» было бы непонятно. Пустая папка — подсказка «В папке нет файлов». Папки разворачиваются в фоновом потоке (сборщик путей), колесо — в потоке интерфейса.
- **Что предложить** (`FolderPlan.Offer`). По **преобладающему типу** (фото, видео… — как группы своего колеса; при равенстве — тот, что раньше в списке типов). Операция предлагается, если каждый файл этого типа она обрабатывает **или он уже в нужном формате** (JPG в папке — для «JPG»), и хотя бы один файл она обрабатывает (папке из одних JPG «JPG» не предлагается). Объединение типов не берём: 300 фото и 2 видео дали бы на колесе смесь из двух наборов. Своё колесо, скрытые и «последний выбор» — по преобладающему типу. «В ZIP» и «В 7Z» для папок не предлагаются: они кладут файлы в архив без подпапок (для архива папки есть «Отправить → Сжатая ZIP-папка»).
- **Что сделать** (`FolderPlan.Plan`). Операция применяется к каждому файлу папки, который она принимает (не только к преобладающему типу); остальные **пропускаются**, их число — в итоговом уведомлении («Пропущено (не подходят): 5»). Файл уже в формате результата (только у конвертаций, `Operation.AlreadyIn`) **копируется как есть**: в `Отпуск (JPG)` должны оказаться все фото, а не только бывшие HEIC.
- **Куда.** `<родитель>\<папка> (<метка>)`; занято — `Отпуск (JPG) (1)` (как `OutputNamer`), папка создаётся сразу при выборе, чтобы две быстрые конвертации не взяли одно имя. «В одну папку» в настройках — `Отпуск (JPG)` внутри общей папки. Подпапки повторяются: `Отпуск\2023\a.heic` → `Отпуск (JPG)\2023\a.jpg`. Пометки операции в именах файлов нет (`Отпуск (сжато)\a.jpg`, а не `a (сжато).jpg`) — она уже в имени папки. Одинаковые имена (`a.heic` и `a.png` → JPG) — `a.jpg` и `a (1).jpg`. Метка: у конвертации — формат без уточнения («PNG (страницы)» → «PNG», «JPG (кадр)» → «JPG»), у инструмента — его пометка («сжато», «1920», «повёрнуто»), без пометки — название. Каждая задача по-прежнему пишет во временный файл в скрытой `.dropwheel-tmp` рядом с результатом и переименовывает в свободное имя (D3); для этого у задачи появилась своя папка результата (`OutputTarget`: папка, основа имени, оставлять ли пометку, копировать ли файл в нужном формате) — `Converter.ConvertAsync(..., target)`, `JobQueue.Enqueue(..., target)`.
- **Объединяющие операции** («Один PDF», «Склеить»): один результат на папку, по имени папки, рядом с ней: `Отпуск (все).pdf`, `Документы (объединено).pdf`; входы — все подходящие файлы с подпапками в порядке проводника. Файлов меньше, чем нужно (одна картинка), — подсказка «нет подходящих файлов».
- **Очередь и уведомления.** 300 фото = 300 задач в той же очереди на 2 (окно задач показывает их как обычно). Уведомления о каждом файле для задач из папки не показываются: когда закончилась последняя задача (`FolderBatch`, ядро), приходит **одно**: «Готово: Отпуск (JPG)», «Файлов в папке: 298», «Пропущено (не подходят): 5 · Не получилось: 2 — подробности в журнале»; кнопки «Открыть» (папка-результат), «Показать в папке», при ошибках — «Подробнее». Всё с ошибкой — уведомление об ошибке; всё отменено — молча. Папка-результат, в которой не оказалось ни одного файла, удаляется (только папка без файлов). Объединяющая операция — обычное уведомление о файле.
- **Смешанный выбор** (папки и файлы вместе): папки — как выше, отдельные файлы — как обычно, рядом с собой.
- **CLI.** `dropwheel convert <папка> <операция>` и `dropwheel list <папка>` — та же логика (удобно для проверки на Linux).
- **Не сделано.** Буфер обмена (Ctrl+Alt+V) по-прежнему берёт только файлы, скопированные папки пропускаются (D-CLIPBOARD). При перетаскивании папки с >1000 файлов колесо показывает «Нечего предложить» (подсказку в трее во время перетаскивания не показываем).
- **Проверка.** `FolderPlanTests` (обход, скрытые, ссылки, предел, преобладающий тип, что предложить, метки на двух языках, план: подпапки, копии, пропуски, свободное имя, «одна папка», Combine, смешанный выбор, уборка пустой папки, порядок имён), `FolderBatchTests`, `ContextMenuRegistrationTests`; интеграционные `FolderConversionTests` (ffmpeg/ImageMagick: подпапки, копия FLAC байт в байт, исходники не тронуты, временных файлов нет, `(1)` при совпадении имён, CLI). На Windows — раздел «Папки целиком» в `manual-tests.md`.

## D-RELEASE. Установщик, стабильные версии, каналы обновлений, winget — принято
- **Версия.** Номер для людей — в `version.txt` (сейчас `0.3.0`), его читает `Directory.Build.props`. CI: тег `vX.Y.Z` → версия `X.Y.Z`; любая другая сборка → `X.Y.Z-dev.<run>`. `AssemblyVersion`/`FileVersion` = `X.Y.<run>.0`: третья часть — номер запуска CI, как и раньше (`0.2.<run>`), поэтому `AppVersion.CurrentBuild` растёт во всех каналах и сборки сравниваются только по нему. Версия для показа — `InformationalVersion` без `+коммит` (`AppVersion.CurrentDisplay`, внизу окна настроек: «DropWheel 0.3.0, сборка 57»). Локальная сборка — `0.3.0.0`, третья часть 0: «сборка разработчика», без самообновления.
- **Каналы.** CI зашивает канал в программу: `AssemblyMetadata("UpdateChannel", "stable"|"dev")` (тег → stable, остальное → dev; нет метаданных — dev, так собраны все до 0.3.0). Настройка `updateChannel` в settings.json: `auto` (по умолчанию — как зашито), `stable`, `dev`; в окне настроек — «Основное → Канал обновлений»: «Как при установке (…) / Стабильный / Тестовый». Тестовый читает `releases/download/dev-build/version.json` (как раньше), стабильный — `releases/latest/download/version.json` (GitHub отдаёт по `latest` самый новый релиз без пометки prerelease); архивы стабильного канала качаются из релиза `vX.Y.Z` из манифеста — пока идёт загрузка, `latest` может смениться. Сменили канал — найденное раньше обновление забывается, новый канал проверяется сразу. Переход со «стабильного» на «тестовый» даёт свежую сборку; обратно — обновление придёт, когда выйдет стабильная версия с бо́льшим номером сборки (отката нет).
- **version.json** — прежний формат плюс необязательные `version`, `channel`, `installer`, `installerSha256`; старые программы новые поля не читают, новые читают старые файлы (поля — null).
- **Установщик** — Inno Setup 6 (`packaging/installer/DropWheel.iss`, CI ставит через `choco install innosetup`, если `iscc` нет): `PrivilegesRequired=lowest`, папка `%LocalAppData%\Programs\DropWheel` (выбор папки скрыт; `/DIR=` и `winget --location` работают), ярлык в «Пуске», задачи «Ярлык на рабочем столе» (выкл.) и «Запускать вместе с Windows» (вкл.; то же значение `Run\DropWheel = "<exe>" --autostart`, что пишет программа), языки English и Русский по языку Windows, запуск после установки. Папка доступна на запись — самообновление из трея работает как в zip-версии. `AppId` `{631AF0D8-69CA-4F61-9028-6FD03A7E2126}` не менять (winget `ProductCode` = `{…}_is1`).
- **Закрытие перед установкой и удалением.** Новый ключ `DropWheel.exe --exit`: просит первый экземпляр через тот же named pipe закрыться (задачи отменяются, значок убирается, движки закрываются) и ждёт до 20 с, пока он отпустит Mutex; код 0 — не был запущен, 2 — закрылся, 1 — не закрылся. Установщик в `PrepareToInstall` вызывает `--exit` у уже установленной версии, затем всегда `taskkill /F /IM DropWheel.exe` (версия до 0.3.0 без `--exit` или zip-копия из другой папки; чужие процессы без прав администратора не завершаются). Без `cmd | tasklist /FI USERNAME`: на ПК Романа эта проверка зависла, и установщик висел на «Подготовке к установке» (сборка 48). Restart Manager (`CloseApplications=yes`) — запасной путь. При тихом обновлении (`winget upgrade`) работавшая программа запускается снова (`--autostart`).
- **Удаление**: `--exit`, `--unregister` (все ключи меню проводника, и старые по расширениям) + удаление основного ключа на случай сбоя, значение автозапуска — если указывает на эту папку, профиль Edge `%LocalAppData%\DropWheel\WebView2`. Файлы, появившиеся после установки (самообновление, `*.old`, `tools\`), удаляются по известным маскам, папка — если пуста. **Настройки и журнал `%AppData%\DropWheel` остаются** (без вопроса — как у большинства программ; повторная установка их подхватит).
- **CI.** Пуш в `main` — как раньше релиз-предрелиз `dev-build`, теперь и с установщиком. Тег `vX.Y.Z` или ручной запуск сборки из `main` с галочкой `release` (тег создаёт сам шаг релиза: из облачной сессии теги не отправляются) — обычный релиз «DropWheel X.Y.Z»: установщик, три архива, `version.json`, архив манифестов winget; описание — раздел `## X.Y.Z` из `docs/CHANGELOG.md` (`build/release-notes.ps1`) и SHA256 установщика. Повторный запуск того же тега заменяет файлы. Если тег и `version.txt` расходятся — берётся тег, в журнале предупреждение. SHA256 установщика печатается в журнале и в сводке запуска, установщик — артефакт `DropWheel-Setup`. Скриншоты и демо-ролик на тегах не делаются.
- **winget.** Идентификатор `Luchano55.DropWheel`, манифесты схемы 1.9 (version, installer, defaultLocale en-US, locale ru-RU) — шаблон в `packaging/winget/<версия>/` (`InstallerSha256: <filled by CI>`). `build/render-winget.ps1` подставляет версию, адрес установщика, SHA256 и дату и раскладывает как в `microsoft/winget-pkgs` (`manifests/l/Luchano55/DropWheel/<версия>/`) — артефакт `winget-manifests` на каждой сборке (на тестовых — для проверки, с адресом на dev-build), к стабильному релизу — архивом. Отправка в winget — автоматически при стабильном выпуске (шаг «Отправка в winget», `build/submit-winget.ps1`: wingetcreate submit с секретом `WINGET_TOKEN` — classic-ключ Романа с `public_repo`; нет секрета — предупреждение, ошибка — не красит выпуск), вручную — workflow `winget.yml` с номером уже выпущенной версии; см. `docs/winget.md`. Для новой версии шаблон копировать не обязательно: берётся самая новая папка.
- **Проверка.** Юнит-тесты: выбор канала, адреса манифеста и архивов, разбор старого и нового `version.json`, `version.txt`, настройка `updateChannel`. Inno-скрипт и шаги CI проверяются первым запуском на windows-latest; установка/удаление — чек-лист «Установщик» в `manual-tests.md`.

## D-WHATSNEW. «Что нового» после обновления — принято
- **Что.** После обновления (самообновление, установщик поверх, winget) через ~2,5 с после запуска по центру основного экрана — окно «Что нового в DropWheel X.Y.Z»: текст изменений с прокруткой, ссылка «Все изменения» (страница выпусков на GitHub, открывается в браузере) и кнопка «Понятно» (Enter / Esc). Фокус не забирает (`ShowActivated = false`). Открыть ещё раз — пункт трея «Что нового» (раздел текущей версии).
- **Откуда текст.** `docs/CHANGELOG.md` вшит в exe (`EmbeddedResource`, имя `CHANGELOG.md`) — тот же файл, что идёт в описание релиза; в сеть окно не ходит. Разбор — в ядре, `ChangelogNotes`: разделы `## X.Y.Z`, вступление файла пропускается; русская часть — до строки `**English**`, английская — после (по `Loc.Current`; английской нет — русская); markdown → текст: `- ` → `•`, строки-продолжения склеиваются, без `**`, обратных кавычек и ссылок. Тестовая сборка `1.2.0-dev.N` берёт раздел `## 1.2.0`.
- **Какие разделы.** Новее прежней версии и не новее текущей (обновились с 1.1.0 на 1.2.0 — 1.2.0 и 1.1.1, с номером над каждым). Прежняя неизвестна или та же (тестовые сборки одной версии) — только раздел текущей. Раздела нет — «Описания этой версии нет…» и ссылка.
- **Прежняя версия.** `settings.json` → `lastSeenVersion` (`AppVersion.CurrentDisplay`, например `1.2.0-dev.57`; старые файлы без поля читаются, null). При запуске: версия ≠ запомненной → окно, затем запоминается текущая (`WhatsNew.ShouldShow`). Поля нет (первый запуск или обновление со старой версии, которая его не писала) — окно только при запуске с `--after-update` (самообновление), при обычном первом запуске — молча. Сборка разработчика (без версии) — никогда.
- **Проверка.** `ChangelogNotesTests` (кириллица, нет раздела, несколько версий, английский, dev-сборка, настоящий CHANGELOG), `AppSettingsTests` (старый файл без поля), скриншоты `whatsnew-light`, `whatsnew-dark` (два раздела), `whatsnew-light-en`; на Windows — раздел «Что нового» в `manual-tests.md`.

## D-BROWSER. Картинки из браузера — принято
- **Что.** Тащите картинку с сайта (Chrome, Edge, Firefox), нажмите Пробел — колесо как для файла её формата; бросили на сектор — картинка сохраняется в папку картинок и конвертируется, результат ложится рядом с ней. Заменяет D5 и закрывает вопрос 2.
- **Когда появляется колесо.** Хуки и `DragDetector` не меняли: колесо и раньше показывалось на любое перетаскивание + Пробел, а что тащат, узнаётся только в `DragEnter` над колесом (данные перетаскивания есть только у OLE, хук их не видит, и разбирать их в обработчике хука нельзя — он должен быть быстрым). Теперь `DragEnter` разбирает данные (`Shell/DragDataReader` в приложении, решение — `BrowserDrag.Resolve` в ядре): файлы → как раньше; картинка → сектора для её формата; только http-ссылка на картинку → «Нечего предложить» с подсказкой «Только ссылка — сохраните картинку и перетащите файл»; **ничего подходящего (текст, ссылка на страницу) → колесо сразу прячется** (раньше висело «Нечего предложить» до отпускания кнопки) — ближе к ТЗ «не появляется при перетаскивании текста». Перетаскивание окна — как раньше: `DragEnter` не приходит, колесо прячется при отпускании.
- **Что берём из перетаскивания, по порядку.** 1) CF_HDROP — обычные файлы. Исключение: один файл во `%TEMP%` при признаках браузера (есть FileGroupDescriptorW или ссылка) — так Firefox отдаёт картинку временным файлом; результат «рядом» оказался бы во `%TEMP%`, поэтому это картинка из браузера. 2) «Виртуальный файл» FileGroupDescriptorW (+ A) + FileContents (первый файл, не папка) — так Chrome и Edge отдают байты картинки. FileContents читается напрямую через COM `IDataObject.GetData` с `lindex` = номер файла (обёртка WPF просит `lindex = -1`, источники на это отвечают ошибкой), из HGLOBAL или IStream; размер из дескриптора обрезает «хвост» HGLOBAL. 3) Готовая картинка: «PNG», «image/png», затем CF_DIBV5 / CF_DIB (+14 байт заголовка → BMP, `BrowserDrag.DibToBmp`; WPF перекодирует в PNG). 4) Временный файл Firefox. 5) `data:image/…` (base64 или %XX) из `<img src>` в HTML (CF_HTML, text/html), text/x-moz-url, UniformResourceLocatorW — раскодируется без сети. 6) http(s)-ссылка на картинку — подсказка. Во всех случаях картинка — только если байты по сигнатуре картинка (`SniffExtension`: JPG, PNG, GIF, WebP, BMP, TIFF, AVIF, HEIC, SVG): у ссылки Chrome тоже кладёт «виртуальный файл» — ярлык `.url`, его колесо не берёт. Больше 200 МБ не читаем.
- **Формат — по байтам, не по имени.** Сайты часто отдают WebP под именем `photo.jpg`: колесо показывает операции для WebP (как для файла `image.webp`, тот же каталог и своё колесо типа «Фото»), файл сохраняется как `photo.webp`.
- **http-ссылки не скачиваем.** Обещание программы — «конвертация офлайн, в сеть ходит только проверка обновлений». Chrome, Edge и Firefox при перетаскивании картинки кладут её байты (FileContents) — скачивание нужно было бы только для редких случаев (картинка-фон, ссылка на картинку, а не сама картинка), а оно тянет за собой прокси, куки, таймауты и вопрос «почему конвертер ходит в интернет». Если байтов нет — подсказка на колесе, в журнале — список форматов, которые прислал источник (чтобы понять, что случилось у Романа).
- **Куда и под каким именем.** Та же папка, что для картинок из буфера обмена (`ClipboardPlan.ImageFolder`): своя папка из настроек, иначе «В одну папку», иначе «Изображения\DropWheel» — одно место и одна настройка для всего, у чего нет «соседней папки» (вместо `Загрузки\DropWheel` из D5). Карточка в настройках переименована: «Картинки из буфера и браузера». Имя — из дескриптора (или временного файла), очищенное от `<>:"/\|?*` и управляющих символов, без пути, не длиннее 80 символов, `CON`/`NUL`… → `_CON`; расширение — настоящего формата (синоним остаётся: `.jpeg`, `.jfif`). Нет имени (PNG/DIB/data:) — `Браузер 2026-10-22 10-31-05.webp` / `Browser ….webp`. Занято — `… (1).webp`; файл создаётся с `FileMode.CreateNew`. Запись — после выхода из `Drop` (браузер ждёт ответа), в потоке UI.
- **«Оставлять исходную картинку»** действует и на картинки из браузера: тот же список `_clipboardImages` и `CleanUpClipboardImage` — после удачной конвертации сохранённая картинка удаляется, если настройка выключена.
- **Буфер обмена.** «Копировать изображение» в браузерах кладёт PNG/Bitmap — работает, как раньше (D-CLIPBOARD). Если в буфере только ссылка на картинку («Копировать адрес картинки» или кусок страницы с `<img>`) — подсказка «В буфере только ссылка на картинку. Скопируйте саму картинку: правый клик → «Копировать изображение»» вместо «В буфере нет картинки или файлов».
- **Проверка.** `BrowserDragTests` (сигнатуры, имя, data:-ссылки, ссылки из HTML, FileGroupDescriptorW/A, CF_DIB → BMP, порядок выбора, временный файл Firefox), интеграционные `BrowserImageTests` (настоящие JPG/PNG/WebP/GIF/BMP/TIFF/AVIF/HEIC, DIB из настоящего BMP читается ImageMagick, WebP под именем `.jpg` сохраняется как `.webp` и конвертируется в JPG, `(1)`). OLE на Linux не проверить — раздел «Картинки из браузера» в `manual-tests.md`.

## D-TRIM. Обрезка видео по времени — принято
- **Что.** Видео → «Инструменты» → «Обрезать…» (`video-trim`) — окно «Обрезать видео»: кадр в месте ручки, полоса из 10 миниатюр, ручки «начало» / «конец», время `мм:сс.д` (начало, длина, конец), галочка «Точно по кадру (дольше, с пересжатием)», «Обрезать» / «Отмена» (Enter / Esc). Результат — `видео (обрезано).<то же расширение>` рядом с исходником по обычным правилам (папка результата, занятое имя → `(1)`); исходник не меняется. Окно открывается из любого колеса — при перетаскивании, из меню проводника, из буфера обмена: все они выбирают через `App.Enqueue`, и там операция с незаданными параметрами уходит в окно, а не в очередь. Только для одного ролика: `MaxFiles = 1` — для нескольких файлов лепестка нет.
- **Как режем.** Без галочки — `-ss <начало> -to <конец> -i <вход> -map 0 -c copy -avoid_negative_ts make_zero`: поиск по входу, все дорожки, без пересжатия — мгновенно и без потерь, но начало — с ближайшего опорного кадра не позже выбранного (видео может начаться чуть раньше). С галочкой — `video-trim-exact`: те же `-ss/-to` до `-i`, кадр и звук пересжимаются как у «Повернуть» (H.264 с CRF из «Видео (CRF)», чётный размер, AAC) → `.mp4`, начало — ровно с кадра. Время для ffmpeg — секунды с точкой (`12.345`) при любом языке Windows. Прогресс считается от длины куска (`FfmpegProgress.For` видит `-ss/-to` перед `-i`).
- **Параметры задачи — общий механизм.** `Operation.Parameters` (имена; в шаблоне — `{start}`, `{end}`) и `Operation.Values` — значения одной задачи (`op.WithValues(...)`; каталог не меняется, очередь получает уже заполненную операцию — сигнатуры `Converter`/`JobQueue` прежние). `ArgumentBuilder` подставляет значения после разбиения шаблона на токены — значение с пробелом остаётся одним аргументом; не задано — ошибка «Для «…» не задано: start, end», значение с `{}` — отказ. У ffmpeg появился `{in}`: если он есть в шаблоне, вход ставится туда (ключи входа — до `-i`), иначе — как раньше, сразу после общих ключей. `VideoTrim` (ядро) — id, разбор времени (`12`, `12,5`, `0:05`, `1:02.5`, `1:00:00`), показ `мм:сс.д`, `Bind(exact, start, end)`; `TrimRange` — логика ручек (не выходят за ролик, не перескакивают друг друга, кусок ≥ 0,1 с).
- **Точный вариант — отдельная операция, не лепесток.** `video-trim-exact` с `OnWheel = false`: его нет в колесе и в настройках колеса (`ForFile`, `WheelGroups.Operations`), его выбирает галочка окна и `--exact` в CLI. Так у каждого варианта свой шаблон и своё правило расширения (копия — тот же контейнер, точная — MP4) без условий в каталоге.
- **Место на колесе.** У видео уже было 8 инструментов (Сжать, 720p, Без звука, Повернуть, Кадры, В ZIP, Субтитры SRT, В 7Z). «Обрезать…» нужнее, чем «В 7Z» для видео (видео уже сжато — 7Z ничего не выигрывает, а «В ZIP» для упаковки нескольких роликов остаётся), поэтому «Обрезать…» стоит после «Повернуть», а «В 7Z» стал девятым и по умолчанию не виден: колесо берёт первые 8 (`WheelArrangement`), в «Настройки → Колесо → Видео → Инструменты» он помечен «не виден» и поднимается стрелками. Лимит 8 не поднимали (геометрия колеса), «Обрезать» не переносили в «Конвертацию» (там — форматы). Тест «не больше 8 на режим» знает это единственное исключение. У тех, кто уже менял порядок инструментов видео, новая операция встаёт в конец своего порядка (как любая новая) — её нужно поднять в настройках.
- **Предпросмотр — кадры от ffmpeg, без проигрывателя.** `MediaElement` (Media Foundation) на части компьютеров не открывает MKV/WebM и зависит от кодеков Windows, поэтому кадр делает сам ffmpeg: `-ss t -i вход -frames:v 1 -vf scale=640:-2` во временный PNG; пока ручку тянут — с задержкой 120 мс, прежний запрос отменяется (процесс убивается); у самого конца ролика, где кадра может не быть, берётся чуть раньше. Полоса миниатюр — 10 кадров по 160 px по очереди в фоне. Длительность — из «Duration:» у `ffmpeg -i` (ffprobe не нужен, хотя он и лежит в `tools`); если там «N/A» (запись экрана из браузера в WebM) — ролик пробегается копированием в `-f null` и берётся последнее `time=`. Не прочиталось — в окне «Не удалось прочитать видео», «Обрезать» недоступна. Воспроизведения в окне нет: кадра в месте ручки достаточно, чтобы попасть в нужный момент, и это одинаково работает для любых форматов.
- **Временные файлы.** Кадры — `%TEMP%\DropWheel\trim-<id>\*.png`: каждый читается в память и сразу удаляется, папка — при закрытии окна (несколько попыток: убитый ffmpeg мог ещё держать файл). Сама обрезка — обычным `Converter` (скрытая `.dropwheel-tmp` рядом с результатом).
- **CLI.** `dropwheel-cli convert <видео> video-trim --start 0:05 --end 0:12 [--exact]`; без `--start` — с начала, без `--end` — до конца; неверное время, конец раньше начала или эти ключи у другой операции — ошибка использования.
- **Вид.** Как окно настроек (D-SETTINGS): системный заголовок, Mica в Windows 11 22H2+, тема и акцент Windows на лету, элементы нарисованы в коде (`TrimTimeline` — шкала с ручками; клавиатура: ←/→ на 0,1 с, с Shift — на 1 с, Home/End, Tab — другая ручка). Окно — по центру экрана с курсором, выводится на передний план.
- **Проверка.** `VideoTrimTests` (каталог, колесо, параметры, аргументы обоих режимов, время, ручки, длительность, прогресс), интеграционные `VideoTrimConversionTests` (настоящий ffmpeg, `Мои фото/тест 1.mkv` 3 с → 1…2 с: копия ≈1 с в MKV с теми же кодеками, точная — 1 с H.264/AAC в MP4; исходник не тронут, временных нет; CLI; кадр и длительность, WebM без длительности), скриншоты `TrimScreenshots` (светлая/тёмная, загрузка, ошибка, английский). На Windows — раздел «Обрезка видео» в `manual-tests.md`.

- **GIF из куска (1.2.0).** В окне — «Результат: Видео / GIF» (пилюли). «GIF» — скрытая операция `video-trim-gif` (`OnWheel = false`, как `video-trim-exact`): `-ss {start} -to {end} -i {in}` + та же цепочка, что у «GIF» для целого ролика (`-an`, 15 кадров/с, не шире 640 px, `palettegen`/`paletteuse`, `-loop 0`; общая константа в каталоге) → `видео (кусок).gif` (англ. « (clip)»). У GIF галочки «Точно по кадру» нет (GIF всегда пересжимается, начало — ровно с кадра), кнопка — «Сделать GIF». Кусок длиннее 30 с (`VideoTrim.GifLongSeconds`) — подсказка «GIF выйдет очень большим», не запрет. CLI: `video-trim --gif` или `video-trim-gif` с `--start/--end`; `--gif` вместе с `--exact` — ошибка использования. Тесты: `VideoTrimGifTests`, `VideoTrimGifConversionTests` (настоящий ffmpeg: `Мои фото/тест 1.mkv` 3 с → 1…2 с: файл начинается с `GIF89a`, ffprobe — gif ≈1 с, 800×450 → 640×360), скриншот `trim-light-gif`.

## D-CROP. Обрезка картинки — принято
- **Что.** Картинка → «Инструменты» → «Обрезать…» (`img-crop`) — окно «Обрезать картинку»: картинка вписана целиком, рамка с 8 ручками (углы и середины краёв тянут, изнутри — двигают; стрелки клавиатуры — на 1 px, с Shift — на 10), вне рамки — затемнено, внутри — линии третей; под картинкой — размер рамки `Ш × В` в пикселях исходника, в заголовке — размер картинки. Пропорции пилюлями: «Свободно», «1:1», «4:3», «16:9», «Как было» (у вертикальной картинки подписи и пропорции — «3:4», «9:16»); выбор пропорции ставит самую большую рамку с ней по центру, дальше углы и края её сохраняют (угол — от противоположного угла, край — вокруг центра). «Обрезать» / «Отмена» (Enter / Esc); вся картинка в рамке — «Обрезать» недоступна. Результат — `фото (обрезано).<то же расширение>` (англ. « (cropped)») по обычным правилам; исходник не меняется. Открывается тем же путём, что окно обрезки видео (`App.Enqueue` → `AskValues`, D-TRIM). Только одна картинка (`MaxFiles = 1`); для папок нет — `FolderPlan` пропускает операции с параметрами.
- **Как режем.** `magick вход[0] -auto-orient -crop {w}x{h}+{x}+{y} +repage -quality {jpgq} выход` — область в пикселях уже повёрнутой по EXIF картинки; `+repage` убирает смещение «холста» (иначе PNG/GIF помнят его). Формат — как у других инструментов картинок (`OutputRule.Same("jpg", RasterKeep)`: JPG/PNG/WebP/BMP/TIFF/GIF остаются собой, HEIC/AVIF/PSD/RAW → JPG). У GIF берётся первый кадр, как у остальных инструментов. Прозрачность PNG/WebP сохраняется (белый фон подкладывается только для JPG, как везде).
- **Предпросмотр — от ImageMagick.** Окно делает копию `вход[0] -auto-orient -print "%w %h" -resize 1600x1600> png` (`ImageProbe`): один запуск даёт и размер полной повёрнутой картинки, и копию для показа. Так поворот на экране совпадает с результатом, и открываются все форматы, которые программа конвертирует (WPF сам не читает HEIC/AVIF/PSD/RAW и по-своему относится к EXIF). Рамка хранится в пикселях исходника, копия только рисуется. PNG — в `%TEMP%\DropWheel\crop-<id>\`, читается в память и сразу удаляется, папка — при закрытии окна. Не открылось — «Не удалось открыть картинку», «Обрезать» недоступна.
- **Ядро.** `CropRect` (X, Y, W, H; разбор `WxH+X+Y` или `WxH`, «x» можно русской «х» или «×»), `ImageCrop.Bind` (подрезка по картинке; область целиком за краем — ошибка), `ImageCrop.Drag` (логика ручек с пропорцией и без, рамка не выходит за картинку и не меньше 24 px на экране), `ImageCrop.Largest`, `ImageCrop.Aspect`.
- **Место на колесе.** У картинок было 6 инструментов (Сжать, ×2, 1920, Без метаданных, В ZIP, В 7Z) — «Обрезать…» стал седьмым, после «Без метаданных»; лимит 8 не задет, ничего не прятали.
- **CLI.** `dropwheel-cli convert <картинка> img-crop --crop 800x600+100+50`; область подрезается по картинке (размер узнаёт ImageMagick), без `--crop`, с неверной областью, областью за краем или `--crop` у другой операции — ошибка использования.
- **Проверка.** `ImageCropTests` (каталог, колесо, аргументы, разбор, подрезка, пропорции, ручки), интеграционные `ImageCropConversionTests` (настоящий ImageMagick, `Мои фото/тест 1.*`: точный размер, `(1)` при повторе, исходник не тронут, PNG с прозрачностью, JPEG с EXIF-поворотом — показ и обрезка повёрнуты одинаково, CLI), скриншоты `CropScreenshots` (`crop-light`, `crop-dark`, `crop-light-en`). На Windows — раздел «Обрезка картинки» в `manual-tests.md`.

## D-PDFPASS. Пароль на PDF: «Защитить…» и «Снять пароль…» — принято
- **Что.** PDF → «Инструменты» → «Защитить…» (`pdf-protect`) — окно «Защитить PDF паролем»: «Пароль», «Повторите пароль», «Показать пароль»; «Защитить» доступна, только когда пароль не пустой (не из одних пробелов) и повтор совпадает (`PdfPassword.CanProtect`), иначе под полями — «Пароли не совпадают». «Снять пароль…» (`pdf-unlock`) — окно «Снять пароль с PDF» с одним полем. Enter / Esc. Результат — `документ (защищён).pdf` / `документ (без пароля).pdf` (англ. « (protected)» / « (unlocked)») по обычным правилам; исходник не меняется. Только один PDF (`MaxFiles = 1`), для папок нет (`FolderPlan` пропускает операции с параметрами). Открывается тем же путём, что окна обрезки (`App.Enqueue` → `AskValues`, D-TRIM). Подписи на колесе короче, чем в ТЗ («Защитить паролем…» — 17 знаков, а в лепесток входит 16): «Защитить…» / «Снять пароль…», полное название — в заголовке окна.
- **Как.** qpdf. Защитить: `--encrypt --user-password=<п> --owner-password=<п> --bits=256 -- <вход> <выход>` — AES-256 (R6), пароль на открытие = пароль владельца: кто знает пароль, тот может всё (печать, копирование), без пароля файл не открыть. Длинная форма ключей (qpdf 11+, на Windows ставится последний) — пароль, начинающийся с «-», не примется за ключ. Снять: `--password=<п> --decrypt <вход> <выход>`. qpdf «invalid password» → у «Снять пароль» — «Неверный пароль», у «Защитить» (PDF уже с паролем) — «PDF уже защищён паролем — сначала снимите пароль». PDF без пароля «Снять пароль» просто копирует (qpdf не возражает). Пароль с пробелами по краям и кириллицей работает (UTF-8; так его и требует AES-256).
- **Пароль — секрет.** `Operation.SecretParameters` (имена параметров-секретов) — общий механизм. (1) **Не в командной строке:** Converter переносит каждый аргумент с паролем во временный файл (`.dropwheel-<id>.arg` в скрытой `.dropwheel-tmp` рядом с результатом, одна строка UTF-8 без BOM), а qpdf получает `@файл` — qpdf сам читает аргументы из файла (`SecretArguments.MoveToFiles`; ключ `--password-file=` есть только для снятия, а `@файл` подходит обоим). Файл удаляется сразу после запуска qpdf (finally), в том числе при ошибке и отмене. (2) **Не в журнале:** строка запуска `> qpdf …` содержит только `@…`, и вдобавок весь журнал задачи, текст и подробности ошибки проходят через маску «••••••» (`SecretArguments.Mask`). (3) **Не в настройках:** запоминается только id операции (последний выбор), пароль — нет; после закрытия окна он живёт только в задаче в памяти, пока она идёт. Значение-секрет подставляется в шаблон последним (меткой), поэтому в пароле можно `{}` и `{in}` — у обычных параметров скобки запрещены.
- **Место на колесе.** У PDF было 6 инструментов (Склеить, Разбить, Оптимизировать, В ZIP, В 7Z, Повернуть ↻) — новые стали 7-м и 8-м, лимит 8 не превышен, ничего не прятали (`HiddenByDefault` не понадобился). Для одного PDF видно 7 (нет «Склеить»), для нескольких — «Склеить», ZIP, 7Z.
- **CLI.** `dropwheel-cli convert <файл.pdf> pdf-protect|pdf-unlock --password <пароль>`. Пароль в командной строке видят другие программы этого компьютера — сказано в справке; в подробном журнале (`-v`) пароль замаскирован. Без `--password`, с пустым или у другой операции — ошибка использования.
- **Проверка.** `PdfPasswordTests` (каталог, колесо PDF = 8, папки, подписи, аргументы, пароль с `{in}` и `-`, маска, файлы `@…`, логика кнопки), интеграционные `PdfPasswordConversionTests` (настоящий qpdf, `Мои фото/тест 1.pdf`: защищён — `--requires-password` = 0, AESv3, открывается с паролем; снят — не зашифрован, 3 страницы; неверный пароль — «Неверный пароль», результата нет; повторная защита — понятная ошибка; исходник не тронут, временных и `@…` нет; в журнале, ошибке задачи и `-v` CLI нет пароля), скриншоты `PasswordScreenshots` (`pdf-password-light`, `pdf-password-dark`, `pdf-password-light-en`, `pdf-password-light-mismatch`). ## D-HOTKEY. Своя горячая клавиша — принято
- **Полноэкранные приложения** (1.1.1, жалоба Романа: в игре «окно без рамки» зажатая мышь + Пробел открывали колесо). В момент нажатия горячей клавиши при зажатой кнопке детектор спрашивает `SuppressWheel` → `FullscreenApp.IsActive`: окно под фокусом без заголовка (нет WS_CAPTION) закрывает весь свой монитор и это не рабочий стол/панель задач (`FullscreenRule`, тесты) — тогда колесо не открывается, клавиша не глотается. Развёрнутый проводник при скрытой панели задач — с заголовком, не считается.
- **Что.** «Основное» → «Горячая клавиша»: кроме готовых пилюль — «Своя…». Щелчок → «Нажмите клавишу… (Esc — отмена)»; следующее нажатие в окне настроек (`PreviewKeyDown`, `Key.System` → `SystemKey`, IME/«мёртвые» клавиши — их настоящая клавиша, `KeyInterop.VirtualKeyFromKey`) становится горячей клавишей и применяется сразу.
- **Хранение.** `AppSettings.Hotkey` — строка, как раньше: клавиша из списка — её имя (`F8`, `Space`), иначе `vk:0xNN` (код виртуальной клавиши, hex). Разбор и подписи — в ядре (`Hotkeys.ToVirtualKey / FromVirtualKey / Check / DisplayName`); старые имена читаются как раньше; неизвестное или запрещённое имя при загрузке → Пробел.
- **Нельзя:** Ctrl, Shift, Alt, Win (левые и правые) — во время перетаскивания Windows ими выбирает «копировать / переместить / ярлык», Win открывает «Пуск» (D7); Esc — закрывает колесо и отменяет перетаскивание; Enter — подтверждение в окнах и меню, легко нажать случайно; Print Screen — занят снимком экрана Windows, и WPF/Windows часто не присылают его нажатие; кнопки мыши, Sleep, служебные коды IME. Окно отвечает коротким объяснением и продолжает ждать.
- **Можно с оговоркой:** буквы, цифры, знаки, цифровой блок. Хук глотает горячую клавишу **только** пока идёт перетаскивание (кнопка зажата и курсор сдвинут) или открыто колесо (`DragDetector.KeyDown`: глотается лишь нажатие, вызвавшее действие, и его отпускание). В остальное время буква печатается как обычно; под пилюлями — предупреждение, что во время перетаскивания она не печатается.
- **Не изменилось:** детектор и хук работают с кодом VK, защита от «залипшей» клавиши (D22) — по любому коду; подсказки в окне задач и при запуске берут `Hotkeys.DisplayName` («Num 5», «Tab», «Q»).
- **Проверка.** `HotkeysTests` (туда-обратно, неверные строки, запрещённые клавиши, детектор принимает любой разрешённый код, буква глотается только при перетаскивании), `AppSettingsTests.Hotkey_is_sanitized`, скриншоты `settings-*-general-custom-key` / `-key-capture`, на Windows — пункт 2а «Этапа 4» в `manual-tests.md`.

## D-BEAUTIFY. Оформить картинку — принято
- **Что.** Картинка → «Инструменты» → «Оформить…» (`img-beautify`) — окно «Оформить картинку»: живой предпросмотр результата на шахматке (видна прозрачность), фон кружками-образцами — «Закат», «Небо», «Мята» (мягкие диагональные градиенты), «Белый», «Серый», «Тёмный», «Прозрачный»; ползунки «Отступ» (0–25 % от короткой стороны, по умолчанию 8) и «Скругление» (0–100 px исходника, по умолчанию 12), переключатель «Тень» (включён); в заголовке — размер «было → станет». Кнопки «Копировать», «Сохранить» (Enter), «Отмена» (Esc). Результат — всегда PNG (прозрачные углы и фон): `фото (оформлено).png` / `photo (styled).png` по обычным правилам (папка результата, занятое имя → `(1)`); исходник не меняется. Без цветовой палитры и своих цветов — нарочно просто. Окно открывается с последним выбранным оформлением (в памяти, до выхода из программы).
- **Как рисуем — одна команда ImageMagick** (шаблон `ImageBeautify.Args`, значения — `ImageBeautify.Values(стиль, ширина, высота)`):
  `вход[0] -auto-orient -colorspace sRGB +repage -alpha set ( +clone -alpha transparent -fill white -draw "roundrectangle 0,0 W-1,H-1 R,R" ) -compose DstIn -composite -repage +P+P ( +clone -background black -shadow 40xS+0+O ) +swap ( -size (W+2P)x(H+2P) -define gradient:angle=135 <фон> ) -insert 0 -background none -compose Over -layers flatten -depth 8 выход.png`.
  Скругление — DstIn с белым скруглённым прямоугольником на прозрачном (прозрачность исходника сохраняется; CopyOpacity её бы затёр); у радиуса 0 — `rectangle` (`roundrectangle … 0,0` ImageMagick 6 не рисует вовсе — картинка пропала бы). Сдвиг на отступ — `-repage`, тень делается из уже сдвинутой копии (`-shadow` сам добавляет к смещению размытие и сдвиг), холст нужного размера встаёт первым слоем, `-layers flatten` рисует всё на нём (что вышло за край — обрезается). Фон — `gradient:#a-#b` (угол 135°), `xc:#цвет` или `xc:none`. Тень: размытие 2,5 % короткой стороны (2…100 px), сдвиг вниз — 0,6 размытия, непрозрачность 40 %; без тени — та же команда с тенью 0 % (один шаблон, условий в каталоге нет). `-colorspace sRGB` — CMYK и серые картинки к виду фона; `-depth 8` — градиент иначе даёт 16 бит.
- **Значения зависят от размера картинки** (отступ в px, маска, холст), поэтому параметры операции — производные: `{mask} {pad} {shadow} {canvas} {bg}`; размер знает окно (копия от `ImageProbe`) и CLI (`ImageProbe.SizeAsync`). Пользовательский стиль — `BeautifyStyle` (запись `bg=sunset;pad=8;radius=12;shadow=1`).
- **Предпросмотр.** При открытии — `ImageProbe.PreviewAsync` с копией ≤ 1000 px (повёрнута по EXIF; размер копии — из заголовка PNG, `ImageProbe.PngSize`, точно до пикселя: по нему считаются маска и холст). Копия лежит в `%TEMP%\DropWheel\beautify-<id>\` до закрытия окна; каждое изменение через 120 мс (как у окон обрезки; прежний запуск убивается) рисует тем же шаблоном на копии (`ImageBeautify.ForPreview` — радиус в масштабе копии, отступ и тень и так считаются от её размера), PNG читается в память и удаляется. Папка удаляется при закрытии (несколько попыток).
- **«Копировать»** — полный размер во временный PNG → в буфер картинкой (Bitmap + формат «PNG» с прозрачностью), без файла рядом с исходником; внизу окна — «Скопировано в буфер обмена».
- **Место на колесе.** У картинок было 7 инструментов для одной картинки (Сжать, ×2, 1920, Без метаданных, Обрезать…, В ZIP, В 7Z) — «Оформить…» стал восьмым, после «Обрезать…»; лимит 8 не задет, ничего не прятали. «Один PDF» (от 2 файлов) и «Обрезать…»/«Оформить…» (только один файл) вместе на колесе не бывают, поэтому проверка каталога (`CatalogTests`) считает отдельно колесо одного файла и нескольких, а список «Настройки → Колесо» помечает «не виден» по счёту для одного файла (иначе «В 7Z» у фото ложно считался бы девятым).
- **CLI.** `dropwheel-cli convert <картинка> img-beautify [--style "bg=sunset;pad=8;radius=12;shadow=1"]`; без `--style` — по умолчанию, недостающие ключи — по умолчанию; неверный стиль или `--style` у другой операции — ошибка использования; картинка не открылась — «Не удалось открыть картинку».
- **Проверка.** `ImageBeautifyTests` (каталог, колесо из 8, стиль и разбор, размеры и ограничения, аргументы целиком, радиус 0, предпросмотр), интеграционные `ImageBeautifyConversionTests` (настоящий ImageMagick, `Мои фото/тест 1.*`: размер = исходник + 2 отступа, `(1)` при повторе, исходник не тронут, прозрачный фон — углы прозрачны, тень темнит отступ, предпросмотр на копии, CLI), скриншоты `BeautifyScreenshots` (`beautify-light`, `beautify-dark`, `beautify-light-en`). На Windows — раздел «Оформить картинку» в `manual-tests.md`.

## D-COPYRESULT. Копировать результат в буфер обмена — принято
- **Что.** «Основное» → «Копировать результат в буфер обмена» (`copyResultToClipboard`, по умолчанию выключено; под «Куда класть результат»). Когда включено, готовый результат сразу кладётся в буфер: одна картинка PNG/JPG/WebP/BMP/TIFF — картинкой (Bitmap для Paint/Word/мессенджеров + формат «PNG» с прозрачностью) **и** файлом (CF_HDROP — вставка в проводнике); всё остальное — файлом: видео, PDF, архив, GIF (картинкой потерял бы анимацию), ICO, папка-результат (разбить PDF, кадры), несколько результатов сразу. Папка целиком (D-FOLDERS) — папка-результат файлом; Combine (Склеить, В ZIP) — их один файл. Картинка больше 50 МБ или 40 Мп, или которую Windows не открыла, — только файлом.
- **Когда.** В момент уведомления: `Notifier` и так собирает готовые результаты в пачку (секунда тишины, не дольше 3 с) — эта пачка и копируется, а в уведомлении к строке «В папке …» добавляется «· Скопировано в буфер обмена» (у папок целиком — в строке примечаний). Так несколько файлов, брошенных вместе, копируются вместе, а не затирают друг друга.
- **Как.** Что копировать — ядро (`Shell/ResultClipboard.Decide`, юнит-тесты); запись — `Shell/ClipboardWriter` в потоке UI (WPF `Clipboard.SetDataObject(…, copy: true)`; буфер занят — 5 попыток через 100 мс, как у чтения в D-CLIPBOARD). Ошибка копирования — запись в журнал, уведомление без пометки.
- **Проверка.** `ResultClipboardTests`, `AppSettingsTests.Copy_result_setting_round_trips`, скриншот `settings-light-general-copy-result`. На Windows — раздел «Копировать результат в буфер обмена» в `manual-tests.md`.
## D-CAPTURE. Снимок экрана — принято
Первый шаг к тому, чтобы не держать отдельную программу для снимков экрана. Главное требование — лёгкость: ничего не работает в фоне, снимок живёт в памяти только пока открыт оверлей.
- **Сочетание — <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>S</kbd>** (`captureHotkey`, по умолчанию включено; «Основное → Windows»; само сочетание — `captureKeys` в settings.json, например `Ctrl+Shift+PrintScreen` или `F9`, разбор — `Capture.KeyChord`, неверное → `Ctrl+Alt+S`). Почему не другое: Print Screen в Windows 11 обычно открывает системный снимок («Использовать кнопку Print Screen…»), а WPF/Windows часто не присылают его нажатие; <kbd>Win</kbd>+<kbd>Shift</kbd>+<kbd>S</kbd> — системный; <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>S</kbd> — «Сохранить как» во множестве программ. «S» — «снимок» / «screenshot», пара к <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>V</kbd>. Оговорка: <kbd>Ctrl</kbd>+<kbd>Alt</kbd> = <kbd>AltGr</kbd>, а в некоторых раскладках (например, польской) <kbd>AltGr</kbd>+<kbd>S</kbd> печатает букву — тогда сочетание выключают или меняют в settings.json. Регистрация — `RegisterHotKey` (`Input/GlobalHotkey`, как у буфера, D-CLIPBOARD); занято — запись в журнал, пункт трея «Снимок экрана» работает всё равно. Обработчик WM_HOTKEY только ставит снимок в очередь потока UI. Из трея — снимок через 350 мс, чтобы гаснущее меню не попало в кадр.
- **Стоп-кадр до оверлея.** Приложение — Per-Monitor V2 (`app.manifest`), поэтому все координаты — физические пиксели. Сначала мониторы (`EnumDisplayMonitors` + `GetDpiForMonitor`), рамки видимых окон сверху вниз (`EnumWindows`, `DWMWA_EXTENDED_FRAME_BOUNDS` — без тени; без свёрнутых, «спрятанных» DWM, рабочего стола и своих окон), затем один `BitBlt` всего виртуального экрана (`SRCCOPY | CAPTUREBLT`) в DIB → замороженный `BitmapSource` (DIB сразу освобождается). Курсор в кадр не попадает.
- **Оверлей — по окну на монитор** (`Capture/CaptureOverlay`): без рамки, поверх всего, не в Alt+Tab. Так у каждого окна DPI своего монитора: окно ставится `SetWindowPos` точно по границам монитора (дважды до показа и раз после; после `DpiChanged` — ещё раз, как у колеса), а его часть стоп-кадра растянута на окно — пиксель в пиксель при 100 %, 125 %, 150 %. Мышь читается через `GetCursorPos` (физические пиксели виртуального экрана), нажатие захватывает мышь окном — выделение может идти через мониторы с разным масштабом; каждое окно рисует свою часть (`CaptureMonitor.ToLocalDip`). Рамка — ровно 1 физический пиксель снаружи выделения.
- **Выделение** (`Capture/CaptureSession`, ядро, тесты): тянуть в любую сторону — область, подрезанная по экрану, тоньше 2 px — ничего; щелчок (сдвиг ≤ 4 px) — верхнее окно под курсором (подсвечивается заранее; окно почти целиком на одном мониторе, как развёрнутое, подрезается по нему), нет окна — монитор; двойной щелчок / <kbd>Enter</kbd> без выделения — монитор под курсором; новое нажатие — новое выделение. <kbd>Esc</kbd>, правый щелчок, уход в другое окно — отмена. Подпись `Ш × В` — в физических пикселях, над углом выделения (нет места — внутри); панель кнопок — под выделением по правому краю, не влезает — над ним, весь экран — внутри у нижнего края (`CaptureLayout`).
- **Действия** (панель в стиле Windows 11: тема, значки Segoe Fluent Icons): «Копировать» (<kbd>Ctrl</kbd>+<kbd>C</kbd>, <kbd>Enter</kbd>) — в буфер Bitmap и PNG, подсказка в трее; «Сохранить» (<kbd>Ctrl</kbd>+<kbd>S</kbd>) — `Снимок 2026-10-24 15-30-05.png` / `Screenshot ….png` в папку картинок из буфера (`ClipboardPlan.ImageFolder`: своя → «В одну папку» → «Изображения\DropWheel»), занято — `(1)`, уведомление с превью и «Открыть»; «Колесо» — сохранить и открыть колесо в режиме клика (`ShowChooser`), дальше всё как для любой картинки, «Оставлять исходную картинку» действует и тут; «Текст» — только если в Windows есть язык OCR: PNG во временную папку → `OcrEngine.RecognizeLinesAsync` → текст в буфер (временный файл сразу удаляется).
- **Память.** Вырезанная область — отдельная копия пикселей (не держит весь экран); после закрытия оверлея ссылок на снимок не остаётся, и в простое — одна сборка мусора с уплотнением больших объектов, чтобы десятки мегабайт вернулись сразу. Истории снимков нет.
- **Пока не сделано (позже):** подписи и стрелки поверх снимка, ручки для подгонки выделения (сейчас — выделить заново), прокручиваемый снимок, запись экрана, своё сочетание в окне настроек (сейчас — только settings.json), задержка перед снимком, действие по умолчанию без панели.
- **Проверка.** `CaptureTests` (выделение в любую сторону, подрезка, щелчок по окну и монитору, промежутки между мониторами, DPI ↔ DIP, раскладка подписи и панели, имя файла и `(1)`, разбор сочетания, настройки), скриншоты `CaptureScreenshots` (`capture-light`, `capture-dark`, `capture-light-en`, `capture-light-hover`) и переключатель в настройках; на Windows — раздел «Снимок экрана» в `manual-tests.md` (два монитора, 150 %).
- **Своё сочетание в настройках (1.3.0; из «Пока не сделано»).** На карточке «Ctrl+Alt+S — снимок экрана» — «Изменить…» → «Нажмите сочетание… (Esc — отмена)» (как «Своя…» у колеса, D-HOTKEY). Проверка — `KeyChord.Check` (ядро, `ChordCheckTests`): клавиша — буква, цифра, F1–F24 или Print Screen; букве и цифре нужен Ctrl, Alt или Win (одна буква или Shift+буква — набор текста); F-клавиши и Print Screen можно одни. **Win + буква, цифра или Print Screen не принимаются** — их держит Windows (Win+Shift+S — снимок, Win+V — журнал буфера, Win+цифры — панель задач, Win+Alt+R — запись, Win+Ctrl+D — рабочие столы, Win+PrintScreen — снимок в файл и т. д.; почти все буквы с Win заняты), поэтому Win — только с F1–F24. Пока окно ждёт нажатия, своё сочетание снято (иначе Windows отдаст нажатие нам, а не окну); новое сначала пробуется отдельной регистрацией (`RegisterHotKey`) — занято другой программой → под строкой «Сочетание … занято другой программой — осталось …», в настройках остаётся старое; свободно — сохраняется в `captureKeys` и сразу работает. Print Screen окно получает только отпусканием (`PreviewKeyUp`). Скриншот `settings-light-capture-chord`.
- **Снимок с задержкой (1.3.0; из «Пока не сделано»).** Пункты трея «Снимок через 3 с» и «Снимок через 5 с» (не настройка — так проще): у курсора плашка «3… 2… 1…» (поверх всего, не активируется, мышь проходит сквозь неё, у края экрана — с другой стороны), раз в секунду — новая цифра; затем плашка закрывается, через 200 мс (чтобы DWM успел убрать её с экрана) — стоп-кадр, дальше как обычно. Подписи и задержки — `CaptureCountdown` (ядро, тест). Время нужно, чтобы открыть меню или подсказку, которые закрываются от нажатия сочетания.

## D-REPORT. «Сообщить о проблеме» — принято
Чтобы человеку не приходилось объяснять, какая у него версия и что писалось в журнал.
- **Где:** пункт трея «Сообщить о проблеме» и ссылка внизу окна настроек (под «Открыть журнал»).
- **Что делает:** открывает в браузере страницу новой задачи `github.com/Luchano55/dropwheel/issues/new?title=…&body=…` с заполненным текстом и кладёт тот же текст целиком в буфер обмена (подсказка в трее: «Отчёт скопирован…» — если GitHub не подставил текст, его вставляют <kbd>Ctrl</kbd>+<kbd>V</kbd>). Ничего не отправляется само: человек видит текст и сам нажимает «Submit» (нужна учётная запись GitHub).
- **Что в отчёте** (`Diagnostics/ProblemReport`, ядро, `ProblemReportTests`): заготовки «Что случилось» / «Что делали перед этим»; версия, сборка, канал обновлений; Windows (10 или 11 — по сборке ≥ 22000, плюс `Environment.OSVersion` и `RuntimeInformation.OSDescription`); язык интерфейса и язык Windows; какие приложения Office установлены (по ProgID, Office не запускается); последние 40 строк самого свежего журнала (под «спойлером»).
- **Личное из журнала убирается:** папка профиля (точный путь `%USERPROFILE%`, без учёта регистра, с `\` и `/`) и любые `X:\Users\<имя>` (включая короткие `ROMAN~1`) → `%USERPROFILE%`; имя пользователя и компьютера отдельным словом → `<user>` / `<pc>` (имена короче трёх букв не трогаются — совпадали бы с обычными словами). **Имена файлов и остальные папки остаются** — без них не понять, на каком файле сломалось (кириллица, пробелы, расширение); в отчёте написано, что задача видна всем и журнал стоит проверить перед отправкой.
- **Длина адреса** — не больше 7000 символов (GitHub не принимает больше ~8 КБ): не помещается — срезаются самые старые строки журнала и добавляется «Журнал обрезан — полный можно приложить файлом: Win+R → %AppData%\DropWheel\logs». В буфер обмена идут все 40 строк. Всё кодируется `Uri.EscapeDataString` («&», «#», кириллица).

## D-RECORD. Запись экрана — принято
Второй шаг после снимка (D-CAPTURE): короткие ролики «как это сделать» без отдельной программы. Тот же принцип лёгкости: в покое ничего не работает, ffmpeg запускается только на время записи.
- **Запуск.** Сочетание <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>R</kbd> (`recordHotkey`, по умолчанию включено, «Основное → Windows»; само сочетание — `recordKeys` в settings.json, разбор — `KeyChord`, неверное → `Ctrl+Alt+R`) или пункт трея «Записать экран». «R» — «record», пара к <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>S</kbd> и <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>V</kbd>; <kbd>Win</kbd>+<kbd>Alt</kbd>+<kbd>R</kbd> — системная запись игр, <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>R</kbd> в браузерах — «обновить без кэша». Оговорка про <kbd>AltGr</kbd> — как у снимка. Занято — запись в журнал, пункт трея работает. То же сочетание останавливает запись. Состояния — `RecordSession` (ядро): Idle → Selecting → Recording → Finalizing → Idle; во время выделения и сохранения сочетание ничего не делает, второй «Стоп» — тоже.
- **Выделение — тот же оверлей снимка**, с флагом режима (`CaptureOverlay(..., record: формат)`, `CaptureView(..., record:)`): стоп-кадр, область / щелчок — окно / <kbd>Enter</kbd> — монитор, подпись размера, несколько мониторов и DPI — без копии кода. На панели вместо действий снимка — «MP4 / GIF» (пилюли, последний выбор помнится — `recordGif`) и «● Записать» (<kbd>Enter</kbd>); <kbd>Ctrl</kbd>+<kbd>C</kbd> / <kbd>Ctrl</kbd>+<kbd>S</kbd> в этом режиме не действуют. Оверлей закрывается, ffmpeg запускается через 250 мс — чтобы гаснущий оверлей не попал в первый кадр. Из трея — через 350 мс, как снимок.
- **Чем пишем — ffmpeg `gdigrab`** (он уже лежит в `tools/ffmpeg`, BtbN GPL — с libx264): `-f gdigrab -framerate 30 -draw_mouse 1 -offset_x X -offset_y Y -video_size WxH -i desktop -c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p -movflags +faststart -t 1800`. Координаты — физические пиксели виртуального экрана из оверлея (Per-Monitor V2); у мониторов левее или выше основного они отрицательные — gdigrab считает от левого верхнего угла основного монитора так же. Ширина и высота округляются вниз до чётных (yuv420p) — `ScreenRecord.EvenSize`. Почему не Windows.Graphics.Capture / Desktop Duplication: свой кодировщик и запись MP4 — много кода и WinRT; gdigrab — одна проверенная команда. Минус — BitBlt рабочего стола: окна с защитой от копирования (фильмы в браузере, DRM) получаются чёрными, при 4K возможны пропуски кадров. Риск, который проверяется только на Windows: ffmpeg.exe не объявляет поддержку DPI, а gdigrab сверяет область с границами виртуального экрана из `GetSystemMetrics` (у такого процесса они пересчитаны по масштабу основного монитора). Если основной монитор не 100 %, а второй стоит левее или выше, запись левого края второго монитора может закончиться ошибкой «Capture area … extends outside window area» (ffmpeg выйдет сразу — уведомление «Не удалось записать экран», подробности в журнале). Тогда запасной путь — фильтр `ddagrab` (Desktop Duplication, в той же сборке ffmpeg, координаты монитора в физических пикселях) для области на одном мониторе.
- **Стоп — «q» в stdin** (`ScreenRecorder`, ядро): ffmpeg сам дописывает файл (moov в начало, `+faststart`); не ответил за 15 с — процесс убивается (тогда файл может не открыться). Предел длины — 30 минут (`-t`, ffmpeg останавливается сам; в трее — «Запись остановлена: прошло 30 мин»). При выходе из программы во время записи — «q», ожидание и сохранение MP4 (GIF при выходе не делается).
- **Файл.** Пишется во временный `.dropwheel-*.mp4` в скрытой `.dropwheel-tmp` папки записей (общий механизм `Converter`), затем переносится на свободное имя `Запись 2026-10-24 15-30-05.mp4` / `Recording ….mp4`, занято — `(1)`. Папка: своя папка картинок из буфера (куда снимки — туда и записи) → «В одну папку» → **«Видео\DropWheel»** (не «Изображения»: ролики в «Изображениях» мешают фотоальбомам, а «Видео» — место, где их ищут). GIF — второй ступенью: из временного MP4 операцией «GIF» каталога (та же цепочка: 15 кадров/с, не шире 640 px, palettegen/paletteuse) через обычный `Converter` → `Запись ….gif`; временный MP4 удаляется всегда.
- **Пока пишем.** Тонкая красная рамка (2 физических пикселя) — прозрачное окно поверх всего, мышь проходит сквозь него; пилюля «● 00:12  Стоп» — у области (под ней справа, не помещается — над ней, весь экран — внутри у нижнего края, как панель снимка), не забирает фокус у записываемой программы. Оба окна скрыты от захвата: `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`, Windows 10 2004+ — видны человеку, но не попадают в запись; тогда рамка рисуется по краю самой области. Старее (функция не сработала) — рамка ставится снаружи области (`ScreenRecord.FrameBounds`), пилюля — тоже снаружи, если есть место (при записи всего монитора она попадёт в кадр). В трее — значок с красной точкой, в подсказке «идёт запись 00:12», пункт меню — «Остановить запись».
- **После.** Уведомление «Запись сохранена» с превью, «Открыть», «Показать в папке» и (у MP4) «Обрезать…» — окно обрезки видео (D-TRIM). «Копировать результат в буфер обмена» (D-COPYRESULT) действует и тут — файл в буфер. Ошибка (нет ffmpeg, захват недоступен) — уведомление «Не удалось записать экран» и «Подробнее» (журнал).
- **Пока не сделано:** звук системы и микрофон, пауза, запись окна, которое двигается (пишется область экрана), выбор частоты кадров и качества, запись дольше 30 минут.
- **Проверка.** `RecordTests` (чётный размер, аргументы gdigrab с отрицательными смещениями и при любом языке Windows, порядок ключей, операция GIF, имя и `(1)`, папка, время на пилюле, рамка внутри/снаружи, состояния, настройки), интеграционные `ScreenRecorderTests` (настоящий ffmpeg, вместо экрана — `lavfi testsrc` в реальном времени, папка «Мои фото»: «q» → MP4 H.264 yuv420p; предел длины и `(1)`; GIF из записи — `GIF89a`, MP4 удалён; синхронный стоп при выходе; ошибка ffmpeg — ConversionException без мусора; нет ffmpeg). gdigrab в Linux нет — его проверяет только чек-лист «Запись экрана» в `manual-tests.md` (два монитора, 150 %, монитор левее основного). Скриншоты `RecordScreenshots`: `record-light`, `record-dark-gif`, `record-light-en`, `recording-light`.
