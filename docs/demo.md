# Демо-ролик и сквозной тест

Ролик на 20–30 секунд снимается **с настоящего экрана** сборочной машины GitHub (windows-latest): робот тащит файл в проводнике, жмёт Пробел, бросает файл на сектор колеса — и проверяет, что рядом с исходником появился результат. Это одновременно реклама и сквозной тест всей цепочки «хуки → колесо → очередь → ffmpeg/ImageMagick».

## Где смотреть

- Ветка `screenshots`, папка `<ветка>/demo/`: `demo.mp4`, `demo.gif` (подписи по-английски), `demo-ru.mp4`, `demo-ru.gif` (по-русски), `demo-poster.png`, скриншоты шагов `demo-NN-*.png`, журналы `demo-*-log.txt`.
  GIF для README: `https://raw.githubusercontent.com/Luchano55/dropwheel/screenshots/<ветка>/demo/demo.gif` (в имени ветки `/` заменяется на `-`).
- Или в запуске Actions → задача **demo** → артефакт `demo` (то же самое) и `demo-raw` (сырая запись `raw.mkv`, 7 дней).

## Как перезапустить

GitHub → **Actions** → **build** → **Run workflow** → выбрать ветку → **Run workflow**. Задача `demo` идёт после `windows` (берёт её сборку) при каждом пуше в любую ветку, кроме основной, и при ручном запуске. Она помечена `continue-on-error`: если ролик не получился, сборка и релиз не страдают, но в запуске видна ошибка.

## Как устроено

- `build/demo/record-demo.ps1` — весь процесс: разрешение экрана 1280×720 (если машина позволяет), папка `C:\Demo\Мои файлы` с файлами, нарисованными утилитами из сборки (фото «Отпуск.heic» — или `.jpg`, если ImageMagick не пишет HEIC, — видео «Видео.mov», PDF на 3 страницы, песня), обои-градиент, DropWheel с `DROPWHEEL_DEMO=1` и отдельной папкой данных (`DROPWHEEL_DATA_DIR`, без проверки обновлений и пункта меню), проводник с крупными значками, запись, монтаж, проверка результатов, журналы.
- `tools-src/DemoDriver` — робот на C# (не входит в `DropWheel.sln` и в архив программы): мышь и клавиши через `SendInput` (плавные кривые, ~60 шагов в секунду), значок файла ищет через UI Automation, положение сектора считает тем же кодом, что программа (`DropWheel.Core`: каталог операций и геометрия колеса), пишет экран через `ffmpeg -f gdigrab` и монтирует ролик: вырезает паузы, ускоряет ожидание, добавляет подписи (шрифт Segoe UI), затухание.
- `DROPWHEEL_DEMO=1` — единственное изменение в программе: хук клавиатуры принимает программные нажатия (иначе робот не нажмёт Пробел). В обычной работе переменной нет, поведение прежнее; в журнале DropWheel при включённом режиме есть пометка.
- Тест **не прошёл** (задача красная), если не появились `Отпуск.png` или `Видео (сжато).mp4`, или не собрался ролик. Что случилось — видно по журналу шага, скриншотам `demo-NN-*.png` и `demo-driver-log.txt`.

## Известные ограничения

- Машина GitHub — Windows Server без монитора и мыши: разрешение может не смениться (тогда ролик в 1024×768), курсор без мыши Windows прячет — робот включает «управление указателем с клавиатуры», чтобы он был виден.
- Уведомления Windows («Готово: …») на сервере могут не показываться — прогресс виден в окне задач.
- На HEIC у Windows Server нет эскизов — значок фото будет без картинки (у PNG-результата эскиз есть).
- Положение сектора робот вычисляет, а не видит: если изменится рисунок колеса (радиусы в `WheelControl`), поправить `WheelLayout.DefaultRingRadiusDip` в `tools-src/DemoDriver`. Ошибку покажет проверка результата и журнал DropWheel («Колесо: <операция>»).
- Ролик снимается на виртуальной машине, поэтому возможны редкие подёргивания и пропуски кадров.
