## 1. Что это и что сделано

DropWheel — офлайн-конвертер файлов для Windows 10/11 (C# WPF, .NET 8, живёт в трее). Тащишь файл → Пробел →
под курсором колесо форматов → бросаешь на лепесток → результат рядом с исходником. Второй вход — «Конвертировать…»
в меню проводника. Владелец — Роман (Luchano55), не программист; проект личный, лицензия MIT, репозиторий публичный:
https://github.com/Luchano55/dropwheel

**Выпуски:**
| Версия | Что | Статус |
|---|---|---|
| 0.3.0 | первая стабильная: установщик, каналы обновлений | выпущена, отправлена в winget (заявка ниже) |
| 1.0.0 | + папки целиком, картинки из браузера, обрезка видео, настройки буфера | **выпущена**, текущая стабильная |
| 1.1.0 | + обрезка картинки, своя горячая клавиша колеса, PDF → Markdown («Markdown» через Word и «MD (быстро)»), исправление самообновления | **выпущена**, текущая стабильная; в winget — заявка #459570 |

**Умеет** (полный список — README и `docs/CHANGELOG.md`): фото (HEIC/AVIF/WebP/JPG/PNG/ICO/PDF, сжать, уменьшить,
без метаданных, обрезать), видео и звук (MP4/WebM/GIF/MP3…, сжать, 720p, без звука, повернуть, кадры, обложка, обрезать
по времени), PDF (склеить, разбить, оптимизировать, страницы в картинки, в TXT/DOCX, повернуть), документы Office
(через установленный Office, без Office — часть форматов), архивы (ZIP встроенный, 7Z/RAR/… через 7-Zip), OCR,
папки целиком, буфер обмена (Ctrl+Alt+V), картинки из браузера, окно задач, уведомления, окно настроек
(своё колесо, прозрачность, язык ru/en, своя клавиша, папки), самообновление.

## 3. Сборка, выпуск, обновления (D14, D-RELEASE)

- **Каждый push** в любую ветку → `build.yml`: тесты Linux + Windows, сборка, установщик, скриншоты → ветка `screenshots`,
  демо-ролик (на не-main ветках). **Push в main** → предрелиз `dev-build` («Тестовая сборка N», версия `X.Y.Z-dev.N`).
  Программа Романа (тестовый канал) сама предлагает обновиться.
- **Стабильный выпуск:** из облачной сессии **тег отправить нельзя** (прокси даёт 403). Поэтому: GitHub Actions →
  `build` → Run workflow на `main` с галочкой `release` (через MCP: `actions_run_trigger`, workflow `build.yml`,
  ref `main`, inputs `{"release":"true"}`). Сборка сама создаёт тег `v<version.txt>`, релиз «DropWheel X.Y.Z»,
  описание — раздел из `docs/CHANGELOG.md`. Перед выпуском: раздел `## X.Y.Z` в CHANGELOG, `version.txt`.
  После выпуска поднять `version.txt` на следующую версию.
- Номер сборки = номер запуска CI (третья часть FileVersion); по нему программа сравнивает версии.
- Каналы: стабильный читает `releases/latest/download/version.json`, тестовый — `dev-build`.
- Отсюда **нельзя скачать** релизы и артефакты GitHub (прокси), но api.github.com и git работают; скриншоты —
  `git fetch origin screenshots` + `git show origin/screenshots:claude-round2/<файл>.png > ...`.
  Логи CI — MCP `get_job_logs` (большие сохраняются в файл, искать grep'ом « Failed »).

## 5. Оформление и правила (как я работал)

- **С Романом:** по-русски, коротко, без жаргона: «что сделано → что дальше → что нужно от вас». Для проверки на
  Windows — пошаговые инструкции (что скачать, куда нажать). Ключи/токены он в чат не присылает — только в секреты.
- **Коммиты** — по-русски, в конце строки атрибуции (см. системные указания сессии). Без названий моделей.
- **Не упоминать чужие продукты** (вдохновлялись одним macOS-приложением — Роман попросил убрать отовсюду).
- **UI:** стиль Windows 11 — Mica, светлая/тёмная тема и акцент из системы, Segoe UI Variable, скруглённые карточки
  (`SettingsPalette`, `SettingsControls`, `UiFonts`, `Glyphs` — Segoe Fluent Icons). Новые окна делать по образцу
  `TrimWindow`/`CropWindow`. Все строки — в `Texts.cs` и `Texts.En.cs` (тест требует английский без кириллицы).
- **Скриншоты для README:** только из CI (тесты в `tests/DropWheel.Windows.Tests`, рисованные фейковые картинки,
  фон — `Scenes.cs`). Скопировать нужные из ветки `screenshots` в `docs/assets/screenshots/`; в README.md —
  английские (`*-en.png`), в README.ru.md — русские. Смотреть каждую картинку перед публикацией (уменьшенный PNG
  может обманывать — увеличивать кроп через PIL).
- **README** — два языка с одинаковой структурой: баннер, демо-GIF, как работает, возможности, скриншоты,
  таблицы форматов, установка (установщик / zip / winget), использование, приватность, ограничения, FAQ, планы.
- **Правила кода из ТЗ:** только проверенные аргументы ffmpeg/magick; пути с кириллицей и пробелами — `ArgumentList`;
  исходник никогда не трогается; занятое имя → `(1)`; хуки быстрые. Проверять на `Мои фото/тест 1.*`.
- **Параллельная работа:** крупные задачи — агентами в отдельных worktree, затем слияние в `claude/round2`.
  Конфликты в CHANGELOG/decisions/manual-tests — объединять обе стороны (не брать файл целиком `--ours/--theirs`!).
- Перед push в main — зелёный CI на ветке. Каждую новинку Роман проверяет по чек-листу из `manual-tests.md`.

## 6. Окружение облачной сессии

- .NET: Microsoft SDK 8.0 из packages.microsoft.com (у Ubuntu нет WindowsDesktop SDK) → `/opt/dotnet-ms`,
  ссылка `/usr/local/bin/dotnet`. В новой сессии поставить заново (см. D15 и историю коммитов).
- Утилиты для тестов: `apt install ffmpeg imagemagick libheif-examples qpdf poppler-utils 7zip librsvg2-bin`
  (ImageMagick 6 из Ubuntu; HEIC — через плагины libheif).
- WPF собирается на Linux с `-p:EnableWindowsTargeting=true`, но не запускается — всё UI проверяет CI и Роман.
- Команды: `dotnet build DropWheel.sln`, `dotnet test tests/DropWheel.Tests`,
  `dotnet build tests/DropWheel.Windows.Tests -p:EnableWindowsTargeting=true`.
