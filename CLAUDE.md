# DropWheel

Офлайн-конвертер файлов для Windows 10/11 x64. Тащишь файл мышкой, жмёшь горячую клавишу — под курсором «колесо» форматов; бросаешь файл на сектор — рядом появляется сконвертированный файл. Второй вход — «Конвертировать…» в контекстном меню проводника. Личный некоммерческий проект Романа.

Полное ТЗ: `docs/spec.md`. Принятые решения: `docs/decisions.md`. Открытые вопросы к Роману: `docs/questions.md`.

## Общение с Романом

Роман — не программист в этом проекте. Писать по-русски, коротко, без жаргона, в форме: **что сделано → что дальше → что нужно от него**. Для проверки на Windows — пошаговая инструкция: что скачать, что запустить, куда нажать. Коммиты — на русском.

## Стек

- C# + WPF, .NET 8, приложение в трее.
- Движки — внешние утилиты в `tools/` рядом с exe: **ffmpeg** (видео/аудио/GIF), **ImageMagick** portable (`magick`, изображения, включая HEIC/AVIF), **qpdf** (склеить/разбить/оптимизировать PDF) и **pdftoppm** из poppler (страницы PDF → PNG/JPG).
- Настройки: `%AppData%\DropWheel\settings.json`; логи: `%AppData%\DropWheel\logs\`.
- Тесты: xUnit.

## Структура

```
src/DropWheel.Core/   без UI, кроссплатформенно (net8.0), всё покрыто тестами:
  Conversions/        каталог операций, настройки качества
  Engines/            запуск ffmpeg/magick, прогресс, ошибки
  Jobs/               конвертер (временный файл → свободное имя), очередь на 2 задачи, папки целиком (FolderPlan)
  Settings/ Logging/  settings.json, журнал в %AppData%\DropWheel
  Ipc/                один экземпляр (Mutex), named pipe между экземплярами
  Shell/              записи реестра для меню проводника, сборщик путей (300 мс)
  Input/              DragDetector — логика горячей клавиши при перетаскивании
  Wheel/              геометрия колеса, состояние, размещение на мониторе
src/DropWheel.Cli/    dropwheel-cli.exe convert <файл> <операция>
src/DropWheel/        WPF-приложение DropWheel.exe (net8.0-windows): App (трей, окно задач),
                      Shell (меню у курсора, уведомления, реестр), Input (хуки), Wheel (окно колеса)
tests/DropWheel.Tests/
build/fetch-tools.ps1 скачивает ffmpeg, ImageMagick, qpdf, poppler для Windows (используется в CI)
packaging/            файлы в архив сборки (корень), installer/DropWheel.iss (Inno Setup), winget/ (шаблоны манифестов)
```

Каталог операций — декларативный: одна запись = id, подпись, входные расширения, движок, шаблон аргументов, выходное расширение.

## Этапы

1. **Ядро без UI** — Engines + Conversions + Jobs + CLI + тесты. Готово: `dropwheel convert photo.heic to-jpg` создаёт `photo.jpg`, тесты зелёные.
2. **Трей + контекстное меню** — правый клик по видео → «Конвертировать…» → MP4, приходит уведомление.
3. **Колесо по горячей клавише при перетаскивании** — проводник и рабочий стол, два монитора, масштаб 100%/150%, не появляется при перетаскивании окон/текста.
4. **Настройки и полировка** — окно настроек, автозапуск, смена клавиши.

## Окружение разработки

- Облачная сессия — Linux. Ядро, CLI и тесты собираются и проверяются здесь (нужны .NET 8 SDK, ffmpeg, ImageMagick).
- WPF-проект собирается на Linux с `EnableWindowsTargeting=true`, но не запускается: UI, хуки, контекстное меню и уведомления Роман проверяет на своём ПК по инструкции.
- Сборка для Романа: GitHub Actions (`.github/workflows/build.yml`) — тесты на Linux и Windows, архивы и установщик в предрелиз `dev-build` (только из `main`; программа обновляется сама по `version.json`). Стабильные версии — тег `vX.Y.Z` → релиз с установщиком Inno Setup и манифестами winget (версия в `version.txt`, что нового — `docs/CHANGELOG.md`, как выпустить — `docs/winget.md`, решение D-RELEASE). Отсюда скачать Windows-утилиты нельзя. Рабочие ветки — `claude/*`, в `main` — проверенное CI.
- Скриншоты интерфейса (и демо-ролик) CI кладёт в ветку `screenshots` (`git fetch origin screenshots`).
- .NET здесь: Microsoft SDK 8.0 из packages.microsoft.com (у Ubuntu-сборки нет WindowsDesktop SDK), `/opt/dotnet-ms`, ссылка `/usr/local/bin/dotnet`. Если сессия новая — поставить заново (см. историю коммитов/решение D15).
- Ручная проверка на Windows — `docs/manual-tests.md`.

## Правила работы (из ТЗ, раздел 14)

- Начинать с этапа 1; UI не трогать, пока CLI и тесты не работают.
- Не изобретать конвертацию — только вызывать ffmpeg/magick с проверенными аргументами.
- Хуки — в отдельном классе, с аккуратным снятием при выходе; обработчик хука быстрый, тяжёлое — в другой поток.
- Все пути — с поддержкой кириллицы и пробелов (аргументы процессов передавать через `ArgumentList`, не склейкой строк); проверять на `Мои фото/тест 1.heic`.
- Исходник никогда не перезаписывается и не удаляется; занятое имя → `photo (1).jpg`.
- Перед каждым этапом — короткий план; после — что проверено (автоматически и вручную).
